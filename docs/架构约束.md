## 2. 组织结构=钱径六域 + 平台横切 + 一个判断工作者

（公司架构 v3 结构，PHASE 重建沿用其域界）

- **六域**（写权域）：`数据`（可观测世界，流为唯一正道）/ `研究`（候选+评估卡+投资人请求）/ `投资`（策略生命周期+资金配置）/ `风控`（**唯一 pre-trade 入口** `risk.Check(intent)`，fail-closed）/ `交易`（多腿原子成交，无开仓决策权）/ `账本`（唯一钱账+一仓一判决书，口径 D-013，不改历史行；复盘挂此域）。
- **三条独立性红线**（机检强制，import 方向脚本）：**风控独立于投资 · 账本独立于交易 · 研究独立于执行**。
- **平台横切**（非域，无 KPI/日报/决策权）：platform/infra/ir/api/store/门禁——配置凭据、RPC、推送、调度健康备份。
- **一个判断工作者（LLM）**：判定线=离钱径距离——思考类可用，钱径类永不（下单/签名/记账/风控/采集）。一个 client+角色注册表；调用逐次落 `fin_llm_call` 账（LLM 对 8% 负责）；四铁律：失败落 warn、输出过 schema、无 git/DB 直写、数学归 Go。

## 3. 主流程=一笔钱的旅程（G0–G11）

枚举 → 匹配（缺条件明提请求，禁静默）→ 经济学验证（净 APR 五项拆解，任一无证据=「不可评估」）→ 纸面沙箱 → 晋级（判据表机读，首次真金翻开关）→ 配置 → pre-trade 风控单入口 → 执行（多腿原子/LEGGED 即回滚）→ 看护 → 结算 → 复盘（预估 vs 实际回写）→ 淘汰/升级。

流程里不出现任何「某时去查」（D-033）；提案滞留禁超 SLA。

## 4. 数据面分层（与工程纪律 §1 互训）

- **事件流表**=唯一权威态源，读径带新鲜度门。
- **事实表族**=统计/复盘专用，与态表隔离。
- **冻结列**=档案，非现值。
- venue 差异**隔在适配层**（venue adapter，D-651）——业务面不见 venue 方言。
- 腿级数据各信本腿 venue 回值；跨腿合成值显式标注来源。

只订 `StreamUpdates`；零计算零校验零分页；`web/src/gen` 为 buf 产物（gitignored，构建前须 `buf generate`）。
