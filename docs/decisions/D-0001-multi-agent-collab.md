# D-0001 多 Agent 协作机制

| 字段 | 值 |
|---|---|
| 状态 | 生效 |
| 决策 | `[角色:决策]` @ 2026-10-23 |
| 批准 | 业主（机制选型委托决策设计，业主持翻案权） |

## 背景

PHASE 由多个 Agent 协同工作，角色分 `[角色:决策]` / `[角色:施工]`。需一套机制使跨 session、跨机器的协作不断链、不撞车、可审计。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| 任务单制 + 分支隔离 + 角色标签（选中） | 单=工作入口与审计痕，支=施工隔离，签=说话人身份；三层各司其职 |
| 纯对话标签制 | 无持久工作队列——新进场 Agent 看不见「该做什么/谁在做」；无验收判据 |
| 纯分支制 | 分支只表「在做什么」，不表「该做什么」与「怎么算做完」 |
| 外部工具（GitHub Issues 等） | 状态出仓——git clone 即丢失工作队列；本仓自建文件零依赖 |

## 结论

采用任务单制：任务单存于 `docs/tasks/` 为唯一工作入口，状态机 `草案→已批→施工中→待验→完成`；一单一支；全部 commit 带角色前缀。全文见 `docs/collab.md`。

## 连锁影响

- 一个 session 只任一角；施工不能验收自己的产出
- 决策记录（本目录）为终审档，翻案须立新档
- 协议修订本身也走任务单流程
