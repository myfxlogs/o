## 0. 摘要

**判词：不是最优解，但方向是对的。**

这套系统最值钱的是边界：发现层与钱径物理分离、SG 独占毕业/执行/账本、
提案是唯一动作桥、发现层无 venue 写钥、价格只准 WS 流、陈=不存在。这些是
骨架，不应在本轮讨论中推翻。

问题集中在两处：

1. **桥面被做成了自研双向 CDC**——LISTEN/NOTIFY 当队列、ts 当游标、
   自然键译 id、全表对账当自愈、`fin_proposal` 的 state 列组跨库双主。
2. **状态表规则杀过头**——原始高频行情不存是对的，但派生信号/评估/拒因的
   历史也一起覆盖了。这是唯一“今天不做、明天补不回来”的资产损失。

一句话：**分域的收益是隔离，成本是分布式一致性；现在成本没有被压到最小，
因为桥做成了“双库表镜像”，而不是“单向事件投递”。**

本席建议的目标形态：

- 保留双机分域；
- 桥只搬“发现层产物”，不搬全宇宙原始行情；
- 用持久 outbox + ack 替代 NOTIFY + ts 水印 + 全表对账；
- 提案/评估用自包含身份，不做跨库 id 译码；
- SG 本地订阅钱径所需价格，投影降为 repair；
- 历史走 `arch_*` change-only + 保留期；
- review 归 SG，或至少把“判决”与“钱径状态应用”拆开；
- 权限四角色最小化，环境变量正名。

## 2. 现状判读

### 2.1 六维

| 面 | 判 | 依据 |
|---|---|---|
| 域边界与职责 | **优** | 发现/钱径分离、SG 毕业权、提案唯一桥、发现层无 venue 写钥 |
| 钱径生存性 | **良** | SG 本地 tickers/MT5/私有 WS 保住平仓；mark/index 仍依赖投影 |
| 桥面一致性 | **差** | 字段级双主、自然键译 id、双向回写、序列守卫 |
| 投递可靠性 | **中下** | NOTIFY 非持久、ts 水印、10min 窗、全表对账 |
| 可回溯性 | **差** | ticks/mark/signal/eval/reject 全是状态表，历史不可回查 |
| 阶段成本 | **良** | 双机是 4 核 SG 约束下的合理仲裁；但 dualwrite 未收口 |

### 2.2 做对的，不要动

1. **发现层与钱径物理分离**：采集/蒸馏/研究在 OCI，执行/风控/账本在 SG。
2. **钱径独占毕业权**：paper→probe→live 只在 SG 判，发现层无权决定“动不动钱”。
3. **提案是唯一正向动作桥**：信号/评估永不直接下单（D-0022）。
4. **发现层无 venue 写钥**：只读钥经 readcred 内存取，主权钥/交易钥不出 SG。
5. **价格源律**：价格只准 WS 流径行，REST 只准条款/目录注册面（T-0171）。
6. **失效语义**：数据陈=不存在，读败=fail-closed，歧义单=禁造仓。
7. **技术栈克制**：Go + ConnectRPC + PostgreSQL/TimescaleDB，单二进制，无多余中间件。

### 2.3 图面自相矛盾/漂移（先对账，再讨论方案）

`docs/数据流.md` 有三处不能同时为真：

## 3. 缺陷清单

### P0-1　历史资产被“状态表”规则误杀（不可逆）

**事实（码面）**

- `md_signal` 建表注释直接写“禁时间序列化”，PK=`(kind,key)`
  （`migrations/md_1057_md_signal.sql:1-8`）。
- `md_ticks` PK=`(venue,inst_id)`、`md_mark_index` PK=`(venue,inst_id,channel)`
  （`migrations/md_1049_md_state_tables.sql:12-34`）。
- `fin_opp_eval` 被 T-0126/md_1053 改成 `UNIQUE(inst_id,template,direction)`
  的最新态（`migrations/md_1053_eval_state_table.sql:1-7`）。
- `fin_eval_reject` 也是 `UNIQUE(inst_id,template,direction,reason)`
  （`migrations/fin_0068_fin_eval_reject.sql:7-16`），同键同因只留一行。

**冲突（图面）**

D-0018 §2 明说“fin_* 审计/评估史表（opp_eval/proposal/cashflow 等）
不受本裁约束——它们行小且是事实史，天然留”。T-0126 的止血有现实理由
（25k 行/分、9GB/日），但它把 eval 从“事实史”改成了“最新态”，没有 D 档
收口。今天是两张纸各说各话。

**后果**

- 每天的唯一信号、评估、拒因历史被覆盖；
- 复盘只剩 `fin_review` 的单点判决，无法做“当时信号→后来结果”的校准；
- P5 的 `fin_opp_eval` 资产层没有历史可卖；路线图自己写“现库全为有界
  状态表=无可售资产”。

**这是唯一不可逆的缺陷。** 修法不是恢复全量 tick（会重演 1.2GB/日），
而是分层：

| 层 | 存不存 | 形态 |
|---|---|---|
| 原始 tick/mark | 不存全量 | 活跃集日快照/按需采样 |
| 蒸馏 signal | **存变化** | `arch_signal` append-only，change-only |
| 评估 eval | **存变化** | `arch_eval` append-only，verdict/net_apr 变才写 |
| 拒因 reject | **存变化** | `arch_eval_reject` append-only |
| 决策/账本 | 已存 | `fin_proposal/fin_review/fin_*` 现状 |

建议先上 signal/eval/reject 三张 `arch_*`，再做活跃集行情日快照；
保留期先定 180d，可配置。`arch_*` 只写不读决策路径。

**验收锚**

- 任取 24h，能重建某 key 的 signal/eval 变化序列；
- `arch_*` 行数随“变化次数”增长，不随 tick 数线性增长；
- 决策/执行/风控路径零 `arch_*` 读（grep 机检）；
- 归档写入失败不阻断主写径（异步/旁路，告警可见）。

### P0-2　同一行两个家（已出实害）

**事实（码面）**

- `fin_proposal` 载荷在 md，state 列组在 SG；前向投影不写 state，反向
  `repairProposalStates` 回写（`internal/projector/ops.go:192-249`）。
- `eval_id` 要按自然键译 SG 发号（`internal/projector/evalmap.go:16-64`）。
- `uEval` 用 `ON CONFLICT(inst_id,template,direction)`，PK 撞时
  `max(id)+1` 另发号（`internal/projector/mirror.go:121-130`）。
- 启动守卫 `setval(sgMax+1000)` 自抬 md 序列（`internal/projector/reconcile.go:28-45`）。

**实害（票面/经验库）**

- T-0169 切窗 research 直写 SG 13min，5 条提案落错库、2 个 id 撞号；
- T-0211 记录“dev→OCI 迁期 10 行 + 研究臂 509 行同键异 id，手工归位各救一次”；
- T-0195 序列守卫撞平，重启即崩环，靠 setval 抬位解。

**根因**

不是某个 bug，是模型问题：**一行提案的身份跨两个库，靠收敛启发式维持。**
“一事实一处存”在行级被破坏。

**建议**

- 提案消息自包含：`proposal_uid`（UUID 或 `(origin,id)`）+ payload；
- SG 建 `fin_proposal_admission(proposal_uid, state, retire_reason, retired_at, ...)`，
  admission 态只归 SG；
- md 侧不再承载“被回写的 state”，研究去重读 admission 的只读副本；
- eval 用 `eval_uid`/自然键，不做 id 译码；删除 `max(id)+1` 与序列守卫；
- 不建跨库 FK。

**验收锚**

- 投影臂重启/杀连/双实例（测试环境）不产生重复提案、不撞 id；
- 同一 `proposal_uid` 在两侧可对拍，state 只有一个写方；
- 删掉 `evalmap.go` 与 `setval` 守卫后测试仍绿。

### P1-1　投递不是持久日志

**事实（码面）**

- `internal/platform/events/events.go` 的 LISTEN/NOTIFY 只是唤醒，不持久；
  断线重连后没有“从哪继续”的日志。
- `internal/projector/reconcile.go:191-200` 的 liveness 把水印夹到
  `now-10min`：`wm = max(wm, now-10min)`。当触发器漏帧（T-0194 已证触发器
  会在表重建中丢失）或监听半死时，早于 10min 的行会被永久跳过。
- 启动 `Reconcile(true)` 做全表 id 集差/全量 ts 重拉，是 O(N) 兜底，不是
  常规路径。

**影响**

- 低频表（dcd 目录、macro、funding 结算拍）可能长期停在旧值；
- 桥面故障只能靠“全表对账 + 告警”发现，滞后且不可重放；
- 每加一张桥表就多一套触发器/水印/重刷逻辑，故障面线性增长。

**建议**

PG-md 建 `bridge_outbox`：

```
seq bigserial primary key,
kind text not null,          -- proposal/eval/signal/dcd/macro/...
key text not null,           -- 幂等键
payload jsonb not null,      -- 自包含消息
created_at timestamptz default now()
```

consumer 按 `seq > ack` 读，单事务 apply + 写 `bridge_ack(consumer, seq)`；
重复 apply 幂等；`lag = max(seq) - ack` 进健康板。全表对账降为手动修复
工具，不做常规路径。若不想自建 consumer，可对 outbox 做逻辑复制（表是
append-only，无动态谓词问题）。

**验收锚**

- 杀 projector 于写批中途，重启后零丢行/零重复；
- 断线 30min 后追平，`lag` 可见并归零；
- 启动不再全表扫；单表故障不拖垮其他表；
- outbox 有保留/分区策略，不无限膨胀。

### P1-2　dualwrite 还是现态，分域收益未兑现

**事实（图面/票面）**

- `docs/数据流.md:50-52` 明写现态 `mode=dualwrite`；
- T-0169 仍是“验收-观察中”，T+48h 终切/T+72h 三锚未出；
- T-0193 记录全量泵把投影打到追不平，serve 只减 ~60%，同机制仍可能复发。

**影响**

隧道载荷/SG 写负载仍是“切前全同”，分域的最大卖点（CPU 降 40%、载荷降
80%）尚未证明。正本图把过渡态写成“现态”，下一个 session 会误以为终态。

**建议**

- 数据流加“模式块”：`mode / since / owner / exit criteria / last verified`；
- 按 T-0169 runbook 到期终切 serve；
- 三锚不达→触发 D-0030 反证锚复审，认真考虑“桥收窄/回滚单库”，
  而不是继续加阈值；
- 终切前不做新的桥表扩张。

### P1-3　“提案唯一桥”在权限面不成立

**事实（图面 + 码面）**

- 数据流：`FIN_PG_DSN` 对 `fin_position/fin_strategy/fin_review/fin_strategy_transition`
  读写；`research_rw` 全表读 + 18 表写。
- 码面：`review/run.go:200-220` 直接 `UPDATE fin_proposal/fin_strategy`，
  并写 `fin_strategy_transition`。
- 实害：T-0169 的 13min 直写就是 research 节点持宽写权 + env 双径造成；
  `docs/工程经验库/条目/user-unit-env-path-divergence.md` 在案。

**判**

review 是钱径态的直接写方，却被放在 OCI 并持宽写权。这跟“钱径独占”
冲突；T-0172 的“钱径读写臂”是急诊补丁，不是终态。

**建议（二选一，讨论定）**

- **甲：review 回 SG。** review 是低频判决，不是高吞吐研究；放 SG 的负载
  远小于它带来的边界收益。`fin_review/fin_forward_check` 归 fin；OCI 只留
  纯研究，`FIN_PG_DSN` 写权撤销。
- **乙：判决与状态应用分离。** review 留 OCI，只写“判决”事实；SG 的
  lifecycle 消费判决并应用 `fin_strategy` 态迁。OCI 对 SG 只读 + 追加
  review 表，不直接改钱径态。

无论哪条，`research_rw` 的 18 表写必须收窄：

| 角色 | 权限 |
|---|---|
| `research_ro` | SELECT fin_position/fin_strategy/fin_cashflow + md 只读 |
| `review_rw` | INSERT fin_review/fin_review_verdict；按甲/乙定是否写 fin_forward_check |
| `roster_rw` | INSERT/UPDATE fin_employee_registry |
| `projector_rw` | 八桥镜像 upsert + fin_position/strategy 读 + registry/config |

`collector_rw` 只留 md 面；`projector` 模板从 `collector_rw` 改
`projector_rw`。

**验收锚**

- `research_rw`（或新角色）对 `fin_position/fin_strategy/fin_proposal`
  的 `BEGIN;INSERT/UPDATE;ROLLBACK` 探针必须失败；
- SG 侧 `pg_stat_activity` 不再出现 OCI 来源的 fin 写；
- review 判决链不断：falsified→proposal retired→strategy degraded 仍生效；
- 一个节点只读一个 env 文件，`systemctl --user cat` 与模板一致。

### P1-4　钱径 mark/index 仍跨机

**事实（码面/图面）**

SG 瘦件只订 `funding-rate`（`internal/data/okxws/subscribe.go:24-35`），
mark-price/index-tickers 不订，读投影镜像；图面明确“SG 侧读投影镜像行”。

**影响**

本地 tickers/MT5/私有 WS 保住平仓，但 MTM、`LatestPx` 的 fallback、
非活跃标的估值在 projector 死时 fail-closed。桥仍在钱径关键读路径上。

**建议**

SG 直接订活跃集的 mark-price/index（几百个 inst，成本远低于 4 核余量），
镜像降为 repair/补洞。这样 projector 死只影响“新机会”，不影响“已有仓的
估值/守卫”。

**验收锚**

- 停 projector 30min，已有仓的 MTM/guard/平仓判定仍走本地鲜价；
- SG 新增订阅后 CPU/连接数在预算内；
- mark/index 镜像只做补洞，不作为唯一源。

### P2　观察项（本轮不一定要动）

1. **单机无 HA**：当前资金量可接受。需写 RTO/RPO、做一次还原演练；
   OCI PG-md 备份目前是“schema+config”，archive 上线后要改。
2. **桥的 schema 耦合**：每新增一个信号/表就要加迁移+触发器+镜像分支+
   domain.tsv。等第三个 venue/策略再抽象，不要现在上 Kafka/NATS。
3. **部署模板漂移**：`deploy/o-collecto/compose.yml:8` 还指 5433；
   `deploy/o-projector.env.example:5` 还写 `collector_rw`。模板也是图的一部分。
4. **readcred 粗粒度**：端点一次返回白名单内全部 venue 的只读钥，按臂
   venue 提件的说法未在接口层落实。只读钥影响有限，但可加调用方 token
   或按 venue 参数收窄。

## 4. 目标形态

```
OCI: collector + research + PG-md + bridge_outbox + arch_*
      │  outbox(seq, kind, key, payload) → ack/lag（幂等、可重放）
      ▼
SG:  core + review + PG-fin + 本地 WS 活跃集(tickers/mark/index/funding) + MT5
      proposal 载荷: md 正本；admission/state: SG 正本；无跨库 FK
```

### 4.1 五条原则

1. **桥只搬发现层产物**：proposal payload、eval（可选）、signal（只搬消费的
   kind）、dcd catalog、macro；不搬全宇宙 ticks/mark/funding。
2. **一份事实一个家**：提案载荷归 md，准入态归 SG；eval 用 uid；不译 id。
3. **钱径价格全本地**：SG 订阅覆盖已有仓所需价格，桥死不影响守卫/估值/平仓。
4. **历史 change-only**：原始高频不存，派生状态变化存；`arch_*` + retention。
5. **权限最小化**：四角色、一个 env 文件、`MD_PG_DSN` 正名。

### 4.2 事实归属矩阵（讨论底稿）

| 事实 | 正本 | 副本/消费 | 桥向 | 备注 |
|---|---|---|---|---|
| 行情 tick/mark/funding | md | SG 活跃集镜像/本地共写 | md→SG | 只搬活跃集，桥死有本地生存线 |
| 蒸馏 signal | md | SG 精选 kind | md→SG | `arch_signal` 存变化 |
| 评估 eval | md | SG 被提案引用行 | md→SG | `eval_uid`，不做 id 译码 |
| 提案 payload | md | SG 只读 | md→SG | append-only |
| 提案准入态 | SG | md 只读副本 | SG→md | 独立 admission 表，字段级双主取消 |
| 策略/持仓/执行/账本 | SG | md 只读副本（研究去重） | SG→md | 副本禁写 |
| review 判决 | SG | md 只读（如需要） | SG→md | 甲案 review 回 SG |
| config/roster | SG | md 副本 | SG→md | 现有第九桥/直 beat |
| 历史归档 | OCI | 无 | 只写 | 不进决策查询 |

## 5. 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| **B（选中）桥面收口**：outbox + ack + 自包含 ID + 本地价格 + review 归 SG/判决分离 | 保留分域收益，把分布式一致性成本压到最小；可分阶段，不搞大爆炸 |
| A 现状修补：再加对账/阈值/守卫 | 弃因——把模型问题当运维问题；每加一张表多一套触发器/水印，故障面线性增长 |
| C 回单库 | 条件保留——仅 T+72h 三锚证明分域无净收益时启动；先收窄桥，再回滚，不做情绪化合并 |
| D 通用事件总线（Kafka/NATS/Redpanda） | 弃因——当前规模 outbox 足够；多一套运维面/凭据面/监控面，收益不匹配 |
| E review 回 SG（甲） vs 判决/状态分离（乙） | 待议——甲最简单，乙保留 OCI 研究连续性；两者都必须收窄 18 表写 |

## 6. 分阶段方案

### Phase 0　归档径（P0，先做）

- **范围**：`arch_signal`、`arch_eval`、`arch_eval_reject`；活跃集
  tick/mark 日快照。
- **形态**：append-only，change-only；`arch_*` 不参与决策查询；保留期
  180d 起步，配置化。
- **实现**：优先在写径做 change 判断（避免触发器放大）；行情日快照用
  cron/systemd timer，显式标注“archive-only，非业务刷新”。
- **验收**：§3 P0-1 四锚；P5 能查到历史 signal/eval；主写径延迟无可测变化。
- **风险**：归档写放大；用 change-only + 批量 + 监控行数/延迟。

### Phase 1　桥面收口（P1）

- **范围**：`bridge_outbox` + `bridge_ack`；提案自包含 ID；admission 表；
  删除 eval id 译码/序列守卫；桥表按“发现层产物”收敛。
- **顺序**：先 outbox 双写（旧径保留）→ 对拍 → 切读 → 删旧径。
- **验收**：§3 P1-1/P0-2 锚；杀连/重启/双实例混沌测试零丢零重。
- **风险**：outbox 膨胀；分区/保留/清理策略先定。

### Phase 2　权限与环境正名（P1）

- **范围**：四角色；review 归属（甲/乙）；`MD_PG_DSN` 正名；单一 env 文件；
  模板改 `projector_rw`；`o-collecto` 模板更新或标注 OCI 实际件。
- **验收**：§3 P1-3 四锚；授权清单入档；`systemctl --user cat` 与模板一致。
- **风险**：review 迁移期判决断流；双跑对拍一周再切。

### Phase 3　终切与观测（P1）

- **范围**：T-0169 到期终切 serve；三锚实测；数据流加模式块；`lag`/镜像
  静默/每表新鲜度进健康板。
- **验收**：CPU 降 ≥40%、隧道载荷降 ≥80%、lifecycle 回分钟级、账链哈希不变；
  未达→D-0030 反证锚复审。
- **风险**：终切后投影追不平；保留回滚到 dualwrite 的单命令径。

### Phase 4　价格本地化与扩展（P2）

- **范围**：SG 订活跃集 mark/index；评估镜像表是否还需要 ticks/funding；
  桥表数量收敛；HA/RTO 文档与演练。
- **验收**：停 projector 30min，已有仓估值/守卫/平仓不受影响。
- **风险**：SG 连接数/CPU；先小流量灰度。

## 7. 讨论议题（本轮请逐条给意见）

1. **归档范围/保留期**：只存“消费过的 kind”还是全 kind？180d 还是 1y？
   活跃集行情日快照要不要？
2. **提案身份**：UUID vs `(origin,id)`？admission 独立表 vs 现有
   `fin_proposal` 加列？是否彻底删跨库 FK？
3. **桥实现**：outbox + 自建 consumer vs 对 outbox 做逻辑复制？一个
   outbox 还是 per-kind？ack 粒度（每行/每批/每表）？
4. **review 归属**：甲（回 SG）还是乙（判决/状态分离）？`fin_forward_check`
   和 `fin_template_proposal` 跟谁走？
5. **dualwrite 终切**：具体日期？三锚不达时的回滚/复审阈值？
6. **价格镜像**：`md_ticks/md_funding` 镜像保留还是只留本地？mark/index
   本地订阅的 inst 范围？
7. **HA/RTO**：本轮做不做？archive 上线后 PG-md 备份策略怎么改？
8. **文档治理**：数据流是否加“执行点/现态/最后亲证”列？模板是否纳入
   机检（防止再次 5433/collector_rw 漂移）？

## 8. 总验收锚

| 阶段 | 锚 |
|---|---|
| P0 | 24h 可重建 signal/eval 变化序列；`arch_*` 行数随变化不随 tick；决策路径零读 |
| P1 | 杀 projector 中途零丢零重；断线 30min 追平；重启不全表扫；`lag` 可见 |
| P1 | 提案无 id 译码/序列守卫；同 uid 两侧可对拍；state 单写方 |
| P2 | OCI 对 fin_position/fin_strategy/fin_proposal 写探针失败；单 env 文件 |
| P3 | CPU ≥40%、载荷 ≥80%、lifecycle 分钟级、账链哈希不变 |
| P4 | 停 projector 30min，已有仓估值/守卫/平仓不受影响 |

## 9. 风险与回滚

- **归档**：写放大/延迟——change-only + 批量 + 旁路告警；失败不阻断主写。
- **outbox**：at-least-once——消费端幂等；ack 只在 apply 提交后写；重复
  apply 用 uid/自然键去重。
- **review 迁移**：双跑对拍一周；判决不一致以 SG 侧为准；保留旧径回滚。
- **权限收窄**：先审计现有 SQL，再收权；`BEGIN;...;ROLLBACK` 探针验收；
  避免误伤 report/earn。
- **dualwrite 终切**：保留 `O_CORE_IMAGE`/env 回滚径；终切窗口避开发布窗。
- **不做大爆炸**：每阶段独立验收，前一阶段不绿不启下一阶段。
