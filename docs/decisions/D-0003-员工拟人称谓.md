# D-0003 员工拟人称谓——称呼放行，机制不动

| 字段 | 值 |
|---|---|
| 状态 | 生效 |
| 决策 | `[角色:决策]` @ 2026-10-23 |
| 批准 | 业主令 2026-10-23（原话：「我们把脚本拟人化吧，我更愿意称他们为员工」） |

## 背景

nox 公司架构 v3（D-246）将「员工/花名册」改称「daemon 台账/运行面」——但其推翻的实证病灶是：假组织图（11 部中 4 部零实体）、考勤式日报（LLM 调用烧在人数汇报）、虚席充当员工。称谓本身并非病灶；台账表名 `fin_employee_registry` 自始至终就是 employee 系。业主现令恢复拟人称谓。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| 拟人称谓+机制不变（选中） | 业主偏好得承 + v3 三病灶不复发；称呼是文化层，机制是安全层，两层可分离 |
| 全回 v2 员工制 | 弃——假组织图/考勤汇报/虚席三病灶实证在档，全回=复犯 |
| 维持 daemon 称谓 | 弃——业主明确偏好，且称谓无机制成本 |

## 结论

- **称谓**：daemon 实体/席位对外称**员工**，`fin_employee_registry` 称**花名册**，Dept 标签称**编制**；六域+平台即「部门」称谓的合法挂靠面（域=真实写权边界，无虚部）
- **机制三锁（不可动）**：①台账只登显式注册实体（`Register` 入册、`Beat` 只 UPDATE 不 INSERT、未登记心跳=聚合 warn 不建行）——**虚席=事故**；②汇报不报考勤（员工数/在职率不进日报，money-first 序不含名册段）；③投资人面不见组织图（请求/报告两类不变，前端页名「运行面」）
- 文档/前端/报告落款可用员工语汇；`docs/公司架构.md` 原文不动（称谓层在头注登记）

## 连锁影响

- 凡产出涉及台账面时可用「员工/编制/花名册」语汇，但实体语义=注册 daemon
- PHASE 品牌层如需专称（如「相位班/守相员」），另立 D 档定
