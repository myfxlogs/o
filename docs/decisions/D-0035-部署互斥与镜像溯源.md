# D-0035 SG 部署互斥协议——SHA tag 留痕+SSH 部署锁+出处闸

| 字段 | 值 |
|---|---|
| 状态 | 生效 |
| 决策 | `[角色:决策]` @ 2026-10-28 |
| 批准 | 业主（当日指令「镜像带 SHA tag 留痕这个方法比较好，先做这个固化」） |

## 背景

Claude/Devin 双席并行实证两役撞车：一方从陈树构 `o-core:latest`
船运 SG 盖掉修复码（幽灵列病灶回灌生产零痕迹）；同一分支两端
各自解合并重复落件。病灶面：`o-core:latest` 单 tag=最后写者静默
赢，容器自报不出所跑源码版本；部署路径无互斥原语。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| （选中）SHA tag+SSH 锁+出处闸 | 容器 `{{.Config.Image}}` 自报 o-core:<sha12> 秒对拍源码版；`mkdir /opt/o/.deploy-lock` 原子互斥+holder 留痕；脏树/未并码 HEAD 拒部署，堵陈码盖新码 |
| 候选 B：集群外锁服务（PG advisory lock/Redis） | 弃因——SG PG 是钱径面不挂运维锁语义；另起服务超量级 |
| 候选 C：单席位宣示制（群喊锁） | 弃因——惯例无强制，正是刚被撞穿的现状 |

## 结论

`scripts/deploy_image.sh` 三段固化为部署唯一合法径：
① `o-core:<sha12>` 主 tag+`latest` 别名同层（compose `image:` 改
`${O_CORE_IMAGE:-o-core:latest}` 环境可覆写）；
② SSH mkdir 部署锁，holder=席位@主机+sha+ts，陈锁 30min 或
`O_DEPLOY_FORCE=1` 可抢；
③ 脏树拒、HEAD 不在 origin/master 拒（`O_DEPLOY_ALLOW_UNPUSHED=1`
显式放行回滚/热补）。

## 连锁影响

- 所有席位部署 SG 一律走 deploy_image.sh——直 docker compose 改产
  属绕锁违例。
- 容器 image 显示 `o-core:<sha>` 即当产源码 commit；`latest` 不再是
  真伪依据。
- 后续部署型脚本（o-projector/o-research 臂船运等）同锁同痕推广时
  复用本协议件。
