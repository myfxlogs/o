## 1. 源机制拆解（本 session 亲证，clone 全文勘案）

「让位」分两层，缺一不成立：

1. **布局事实（纯 CSS）**：打开的瓦片占满整行——`.swatch.is-open { grid-column: 1 / -1 }`（源 `styles/instruments.css:1164`）。网格布局自动把同级瓦片挤到新位置。「让位」本身零 JS。
2. **顺滑感（FLIP 动画）**：`flipLayout(targets, mutate)`（源 `composables/motion.ts:488`，20 行）——GSAP Flip 插件 `getState` 量旧位 → mutate 改状态等 DOM 更新 → `Flip.from` 让全部同级瓦片从旧矩形滑到新矩形。即 FLIP 技法（First-Last-Invert-Play）。

源项目配套动效纪律（值得一并吸收的约法）：

- 动效唯一入口 `motion.ts`：缓动/时长 token 化（`EASE`/`DUR`），不在页面复制配方；
- `skipMotion()`：`prefers-reduced-motion: reduce` 与后台页签（`document.hidden`）下补间直落终态；
- **只动 `transform`/`opacity`**，交给动画库的属性不再挂 CSS `transition`（双主必打架）；
- 「每条动效都要说得出语态，说不出语态的就是装饰，不做」。

## 2. 选型

- **选项 A（选定）：无依赖手写 React FLIP hook。** `useLayoutEffect` 量旧位 → 状态更新 → 量新位 → 反向 transform 翻转 → CSS transition 回弹清零，约 60 行。理由：机制本质是「量-翻-放」，我们的使用面（列内/网格内让位，无拖拽、无跨容器共享元素）用不到 GSAP Flip 的 `nested`/`prune`/scale 纠偏重火力；符合架构约束 §1「React 19 + 纯 CSS」与依赖钉表现状（react/connectrpc/uplot 三件）。
- **选项 B（淘汰）：引 GSAP + Flip 插件（源项目同款）。** 弃因：为单一让位动画引整个动效框架（gsap 压缩后数十 KB），Vue 包装层不可复用、React 侧仍须自写桥，两头不占。**翻案口**：动效面扩散到 ≥3 处复杂共享布局（拖拽重排/跨容器变形）时，立新档重议。
- **选项 C（淘汰）：framer-motion `layout`。** 弃因：同 B 整包动画系统，且把动效主战场从 CSS 挪进 JS，与「纯 CSS」约束方向相逆。
- **配套纪律（随机制引入，入 T-0233 验收）**：时序/缓动 token 化（CSS 变量即可）；`prefers-reduced-motion` 直落终态；打断安全（连点后不残留 transform）；`transform`/`opacity` 优先。
