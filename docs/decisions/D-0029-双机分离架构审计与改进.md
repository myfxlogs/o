# D-0029 双机分离架构审计——现态非最优，改进分三级（裁决 2026-10-26）

## 审计对象

业主令：「执行席在 SG 生产机，采集/研究/蒸馏在开发机——二级分离是否最优」。
本席实拍两机取证（SG `docker stats`/`pg_stat_activity`/`pg_stat_user_tables`，
开发机 `systemd`/`ps`，码面 `cmd/core/main.go` + `cmd/collector/main.go` 装配）。

## 实态（与叙述的三处偏差）

| 面 | 叙述 | 实拍 |
|---|---|---|
| 研究臂位置 | 开发机 | **全在 SG `o-core`**：`researchArms`（funding 评估/dcd 枚举/gapscan 差扫/hypothesis 假想官/grammar 文法臂/researcher 看门）+review+report 皆 SG 进程内（`cmd/core/dcd.go:139`） |
| 开发机负载 | 采集+研究+蒸馏 | 仅 `collector` 一个二进（okxws 全宇宙订阅+sigdist 蒸馏+mt5 bridge），**RSS 30MB、CPU 3.7%**——12 核 31G 机器近乎空转 |
| SG 负载 | 执行席 | 4 核 load 2.66、**PG 单进程 CPU 114%**；写放大：`md_mark_index` 3,638 万次写 / `md_ticks` 2,418 万 / `fin_opp_eval` 1,391 万 / `fin_proposal` 122 万；另宿 3 个非 O 容器（alpha-server/alpha-postgres/alphaforge-postgres） |

**结论：现态是「采集外置」一级分离，不是「研究外置」二级分离。** 研究臂
（评估/枚举/假想——纯计算、零钱径）仍压在 4 核钱径机上与 PG 争 CPU。

## 缺陷清单（按害排序）

1. **CPU 争用于钱径机**——研究臂（dcd 枚举 11,164 产品快照×评估、grammar
   文法×能力账笛卡尔枚举、hypothesis 假想官）与执行/风控/账本同机同 PG。
   lifecycle 单扫 ~20min（T-0154 观察行）即此争用的症状；PG 114% 在 4 核=
   钱径查询排队风险。**执行席的延迟预算被研究面的吞吐消耗。**
2. **开发机地址错位**——12 核 31G 跑 30MB 采集器，而 SG 4 核 7G 跑全部计算。
   分离的物理收益（算力隔离）基本没兑现。
3. **写放大源头在远端**——collector 从开发机**经 SSH 隧道**（`:5544→SG:15433`）
   往 SG PG 写 `md_ticks`/`md_mark_index`/`md_signal`（`client_addr=172.22.0.1`
   5 连接）：秒级 tick 行跨公网隧道写入=隧道抖即采集断（mihomo 事故实证，
   T-0141 期），且 PG 写 CPU 全摊在钱径机。
4. **单 PG=单故障域+单隔离域**——采集/研究/钱账三面共一个 PG 实例：研究面
   一次长查询钉 xmin（T-0154 实案）即影响账链 vacuum；无 role 级资源隔离。
5. **SG 非 O 租户**——alpha-*/alphaforge-postgres 三容器共宿钱径机，占 mem
   limit 7.7G×2（现用小但 limit 不隔离）；钱径机应单租。
6. **残名与双影服务**——开发机 `alert-bridge*.service` 仍冠 NOX 名、
   `o-collecto` 命名残（T-0137 已正 `采集器` 但 systemd 单元未随）；
   `mihomo-watchdog` 与采集同宿=网络面自扰源（mihomo 事故）。
7. **开发机既是开发树又是生产采集席**——同机 `/opt/o-wt/*` 施工树与
   `/opt/o-collecto` 生产件共宿，`go test`/`docker build` 峰值可挤采集。

## 改进方案（三级，按收益/风险序）

### Ⅰ 级（零新件·立即）——研究臂迁开发机

- 新二进 `cmd/research`（或 collector 内加 `-arms=research` 开关）装配
  `researchArms` 全族+review；SG `o-core` 去掉 `go researchArms`。
  **修订注记（T-0165 返修裁 2026-10-26）**：report 为钱径读写面（app_secrets/
  master key/fin_cashflow）**留 SG 不迁**——原文「+review/report」中 report 撤。
- 研究臂零钱径（D-0016/T-0102 红线已钉「research 域零 venue 凭据依赖」——
  dcd/gapscan 的 okcli 为公开读面），迁移无凭据分发问题。
- 预期：SG CPU 释放 ≥50%（PG 争用主力是 eval upsert 1,391 万写+枚举读），
  lifecycle 扫拍回归分钟级；开发机算力首次兑现。
- 风险：研究臂仍跨隧道写 SG PG（缺陷 3 不解）——Ⅱ 级解。

### Ⅱ 级（结构件·本周）——PG 分域

- 开发机立 **PG-md**（行情/信号/评估域：`md_*`/`fin_opp_eval`/`fin_opp_hypothesis`
  /`md_signal`），采集+研究臂本地写零隧道；SG **PG-fin**（账链/持仓/执行/
  配置域）只收**蒸馏结果**：`fin_proposal`+`md_signal` 精选键（carry_diff/
  xvenue_spread 等执行面要看的）经逻辑复制或 collector 推送（现 md_signal
  有界表语义天然适合推送）。
- 契约：D-0022「信号陈=不存在」律天然成跨库新鲜度闸——SG 侧消费只看 ts。
- 隧道降级为**低频小载荷**（提案行+信号行 分钟级），抖动容忍度质变。
- 风险：双库=双备份面+双迁移链（`migrations/` 分前缀 `md_`/`fin_` 分流，
  check_migrations 闸已有 `md_*` 键域断言可扩）。

### Ⅲ 级（治理件·择期）

- SG 单租化：alpha-*/alphaforge 三容器迁出或限 cgroup（钱径机不共宿）。
- 开发机职责拆：生产采集/研究席与施工树分 cgroup slice（`systemd`
  `CPUWeight`/`MemoryMax`）+目录隔离。**业主令 2026-10-26：采集留开发机
  （硬件/网络足够），「迁第三台机」项撤。**
- 残名清：`alert-bridge*`→`o-alert-*`、`o-collecto`→`o-collector`（T-0137
  后续面）；`mihomo-watchdog` 与采集席分离（网络面自扰源隔离）。

## 裁决

- **现态非最优**——是采集一级外置，研究面仍压钱径机；地基牢靠（事件脊/
  账链/闸全谱实证）但**算力地址错位**。
- 立即走 Ⅰ 级（立 T-0165）；Ⅱ 级立 T-0166 设计票（PG 分域契约先过设计
  验证再施工——架构级）；Ⅲ 级记路线图不立票。
- 反证锚：Ⅰ 级落地后 SG `o-postgres` CPU 若未降 ≥30%、lifecycle 扫拍
  未回分钟级→研究臂非争用主力，Ⅱ 级优先序重排（转查写放大本体）。
- 自检期限：Ⅰ 级落地 +48h 实拍复核；本裁决 2026-11-09 复审。
