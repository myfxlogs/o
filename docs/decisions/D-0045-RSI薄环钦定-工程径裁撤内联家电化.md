## 背景（实账，勿再议）

- 目标不变：RSI 递归自改进——业主只出资+供条件，机器自己发现/修复/进化成赚钱机器。
- 实现形态错：工程径被建成人类组织仿制品（票/相位/席位/草案/物料化十五环），2026-11-09 全天实账=判决书：
  - 钱径变更 0 行，git/master 面 100% 是工程径自维护；
  - 24h 烧票号 187、草案 532 笔、升件积压 95、check_all 全谱/定向谱 ≥6 趟、戳互抹踩踏 1 场、二进制误提交事故 1 起；
  - 净产出为负——所修问题大半是自产（草案烧号→修进水口、层扫重燃→修豁免、席位踩戳→研踩踏）。
- 实证对照：外派径（业主令→外席施工→外审裁→merge，T-0517/WG 先例）全链干净零积压——认知浓度高、档案手续零。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| **C. 家电+唤知（选中）**：内联=钱径+探测+唤知机+部署管道+PG；认知=信号积阈唤起的 agent 会话；无票/相位/席位/物料化层 | 五环模型（感知→认知→行动→验证→记录）——认知环节从「常驻官僚件」换成「被唤的思维」，环闭合不要人，RSI 成立且 churn 结构性死亡 |
| A. 保留组织仿制环 | 弃因：实账已判——档案系统自产档案，认知含量趋零；机器不需要为人类缺陷（慢/忘/追责）设计的手续 |
| B. 拆两仓（钱径仓/工程仓） | 弃因：耦合在事实层（PG 事件账共享）不在码层；拆仓不解决踩踏（踩踏是进程纪律非仓界），反劈对账面 |

## 结论

**内联常驻件（家电面，全部）：**

1. 钱径——o-core 交易引擎/风控闸/采集（gauges/hostmetrics/喂交易的数据面）
2. 探测薄壳——现有探针砍到「写 ops_event 信号行」为止：只述事实，不分类/不起草/不翻相/不落件
3. 唤知机——唯一新增件：dispatcher 监视信号面，积阈/超时→唤起 agent 会话（最强可用模型）携 runbook 进场「扫信号→处置→落账→收口→死」；会话死=下轮再唤。**被唤的 agent IS 机器在思考**——召唤式与常驻式只是实现细节
4. 部署管道——check_all/green-stamp/mirror_push/三条 tunnel：被动件，有 merge 才醒
5. PG——账本+信号面底座

**裁撤件（工程径全体，停线钦定）：** gateway 分类归领（处理段）/metabus/mech 台账轨/层扫处理段/起草拍 ticketdraft/全部席位拍（ceo/cto/econ 等）/wt-gc/strategy-review——逻辑降级为唤知会话的 runbook 段落，不再是进程。

**免疫层不动：** check_all→绿戳→merge→pre-push 闸链是免疫系统非官僚件；RSI 无免疫=自伤（当日二进制进历史事故为证）。修钱径走全闸。

**业主残留面：** 条件请求（凭据/资本/权限——物理世界件）+ COS 呈报（非事事报——外席批完筛出人级件才呈）。
