## 一、三锚验证结论（证据在案）

### 锚① 域边界——**不过**（1 矛盾+1 漏表；其余 53 表自洽）

- ✗ **fin_paper_fill 自相矛盾**：§三 PG-md 列表含 `fin_paper_fill`（见 §五 争议），
  §五 却裁「归 fin（非 md）」。码面对拍支持 §五：写者 lifecycle/paper.go+
  xvenuepair.go（SG）、读者 promote 记账同文件（SG 侧闭环）——**§三 列表须删**。
- ✗ **position_daily_income 漏表**：SG pg_stat_user_tables 55 表全集逐一对拍，
  唯此表不在 D-0030 任何归属列。写者=pgstore/trx_yield.go+cmd/core/trx_rollup.go
  （trx 钱径面）——**归 PG-fin**。
- ✗ **fin_proposal 写权歧义**：§三 桥面头注「SG 侧为**只读**镜像表」vs §四
  「SG lifecycle 改 state→回写」——直接冲突。须钉写权矩阵：md=行正本（研究列
  唯一写方），SG 镜像仅 lifecycle 写 state 列（fin_armed/fin_retired）。
- ✓ **md_account_events 归 fin 自洽**：写者全集 SG 侧——cmd/core/restlive.go:107、
  okxpriv（core 专用）、mt5/collector.go:254（`mt5.NewCollector` 装配于
  cmd/core/main.go:215 非 collector）、ledger/run.go:277、earn（cmd/core:133）。
  改名残名清列 Ⅲ 级不动摇。
- ✓ **fin_forward_check 归 md 自洽**：写者+读者均 internal/review（研究域，
  随 T-0165 迁）；ev_fwdchk 触发器（0028）本就为研究排期面。
- ✓ 其余 53 表归属逐一对拍无歧义（fin_trx_*×7/fin_cmc_*×4 wildcard 覆盖实表
  全中；md_equity_curve/md_funding=timescale hypertable 归属与现 policy 不冲突）。

### 锚② 同步机制——**b 裁准，反向径须补正**

- ✓ **否 a 站得住**：PG 逻辑复制 row filter 仅本表静态列表达式（禁子查询/
  跨表 join/动态谓词）——「活跃集=fin_position open ∪ fin_strategy 非 retired」
  谓词不可表达；md_mark_index(1,014 写/分)+md_ticks 全表复制=没分域。
- ✓ **否 c 站得住**：拉取方在 SG 仍跨隧道；lifecycle 扫拍 ~20min 再加远程读=劣化。
- ✓ **b 与 D-0008 事件脊同构**：LISTEN 本地 ev_* 零轮询；镜像写
  `ON CONFLICT DO UPDATE WHERE ts>EXCLUDED.ts` 有界语义=D-0018 同形。
- ✗ **反向径指定错帧**：§四「回写走 projector 反向订阅 SG **ev_strategy**」与码
  不符——lifecycle 直改 `fin_proposal.state`（run.go:160/224、xvenuepair.go:27/96），
  **现 trigger 集（0028）无 ev_proposal 帧**；且正向 push 同样缺 PG-md 侧
  fin_proposal INSERT 通知。须双侧补 ev_proposal 触发器，回写订阅改之。
- △ **闭环窗口与自愈**：写回滞后窗内 md 侧 dedupe（0054 同键在途跳写触发器）
  兜住重复提案 ✓；但反向丢帧（projector 死于态变窗）=md 永陈。全表投影语义下
  projector **起动/重连全表对拍**自愈是天然径——须显式入设计（§四）。
- ✓ **projector 死 fail-closed 闭环成立**：T-0128 闸在码（guard/notional.go:12
  tick 新鲜度+facts.go:115 funding 9h 阈）；生存线在案——T-0141「venue='mt5'
  桥写与 **SG 本地采集**同键共存（D-0018 最新赢）」+OKX 私有 WS 在 core，
  存量平仓走 venue 本地径不依赖镜像 ✓。措辞补正：「MT5 本地 tick」应作
  「SG 本地 MT5 采集（T-0141 共写语义）」。
- △ 活跃集发布机制「读一次/分钟 **或** md_active_set 小表」二选一未裁——
  轮询选项与 D-0008 禁快照有张力，**钉 md_active_set+SG notify**。

### 锚③ 回滚径与载荷——**算术过，机制须落地**

- ✓ 载荷算术复核：基线 1,014+522+370+80+~5≈1,991≈2,000 ✓；镜像 215=
  80+50+30+5+10+20+20 ✓；降 89%。**但三处阈值不一致**：T-0166 票面锚
  「≥90%」vs 本档实算「89%」vs D-0030 反证锚「≥80%」——统一（建议锚定
  反证 ≥80%、目标 ≥85%，89% 为预估非承诺）。
- ✓ 活跃集谓词覆盖读面：fin_strategy state ∈ {proposed,paper,probe,live,
  degraded,retired}（0007:7）——「非 retired」覆盖 paper/probe/live 全部
  sizing/ledger/lifecycle 读形（paper.go 按 strategy_id、ledger/run.go:222 按
  持仓 inst、sizing 按 probe/live）。已知良性窗=新武装 inst 等分钟级投影，
  T-0128 闸 fail-closed 兜底（延迟开仓非误开仓）——如实记入 T-0168 验收面。
- ✓ md_macro_event 不投影闭环：读者=research/funding/run.go:196+ledger/report/
  run.go:163，二者均随 T-0165 迁 md（D-0029 Ⅰ级钉 report 同迁）。注：§二
  表「ledger/run.go 读 md_macro_event」与码不符（实际仅 report 读）——文档小误
  随补正顺手正。
- △ **同源 include 无落地原语**：pgstore.Migrate 走 embed FS 整文件执行
  （migrate.go:43 `migrations.FS.ReadFile`），SQL 无 include 机制。§六
  「schema 由 md 链定义文件同源 include」须具体化：**机检径=check_migrations.sh
  桥表 DDL 归一化比对断言**（设计断言②即此——include 与断言是两个机制，
  钉断言弃 include 措辞，或 build 时单源生成双链文件，二选一钉死）。
- ✓ 回滚单步性成立：镜像表 DDL 与正表同形→projector 停+DSN 指回+镜像转正表
  零转换。前提即同源断言成立。
