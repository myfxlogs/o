# D-0004 员工命名与职责卡制

| 字段 | 值 |
|---|---|
| 状态 | 生效 |
| 决策 | `[角色:决策]` @ 2026-10-23 |
| 批准 | 业主令 2026-10-23（原话：「给他们取 1 个名字，约定他们的职责，以此来判断工作是否合格」） |

## 背景

D-0003 恢复员工拟人称谓后，业主进一步要求：员工要有名字、有职责约定、以职责判工作合格。风险面=v2 前车（纸面 KPI/虚构组织）——合格判据必须机读。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| 岗位制+职责卡（选中） | 名挂职能岗不挂人头——无虚席；职责卡=合格判据载体，判据全机读可自算 |
| 人头制（每协程一名） | 弃——协程生灭频繁，名册将成噪声坟场（v3 台账实证：95/143 行是协程噪声） |
| 纸面职责描述 | 弃——不可机检=纸面 KPI 复犯 |

## 结论

立 `docs/员工名册.md`：编制册（设计档），一职一卡（职责/产出/合格判据/越权线），初编 v0 按域列岗。考核三判：出勤在窗、履职产出在窗、不越权。名册=运行时 `fin_employee_registry`，编制=本册，**缺岗/私岗两报**。

## 连锁影响

- 职责卡即各 daemon 的验收判据——实现票/复审可对卡核收
- 补编=先补卡再注册，卡是注册前置
- PHASE 品牌层岗位名暂用职能直名；如需主题专称（相位系）另立 D 档
