（能力债探针火 quarter_basis_long）,其余全由业主质询触发→交互会话修**。
当日自主唤知会话 4 场全部瞬死（spawn env 漂占锁饿死）,零产出,被交互
处置行遮蔽 2.5h 无人知。

D-0045 的感知环是**症状探针**（断流/资金闸/对账/孤儿/唤知/数据缺/
商业/能力债）——只看得见「运行着的东西坏了」。当日 bug 的四类形态它
结构性看不见：

| 形态 | 当日实例 | 为何探针盲 |

**RSI 若只有症状探针,就永远要人来当审计员**。

## 选项与取舍

| 候选 | 取因 / 弃因 |
|---|---|
| **C. 审计臂（选中）**：日拍唤起一场审计会话,按域册轮转,带 code-audit 三维度（同类一致/该在不在/钦定 vs 实现）主动扫不变量；产出受**证据闸**约束——有 RED 测试才升件,否则只记疑点；审计者不修,升件交唤知会话修 | 直击四类盲区；RED 闸杀假阳（误发=唤一场修理会话,代价可见）；审计/修理分席=独立复核+可度量（修复 commit 引 升件#=机发现） |
| A. 把三维度塞进唤知 runbook | 弃因：唤知会话被信号唤起,进场就是修理心态,「顺手审」=不审；且自修自审无独立线 |
| B. 全机械化（只写对齐测试/lint） | 弃因：闭世界——只能抓已想到的类；但**作为棘轮保留**：每个审计确认的缺陷类,修理会话应顺手加机械闸（本批先落两件：esc scope↔runbook 档对齐、execfam↔legShapeOf 对齐） |
| D. 更高频/多域并发审计 | 弃因：配额与噪声；先日拍单域,度量读数证明有产出再扩 |

## 结论

**新增件（全部薄壳,无常驻进程）：**

1. `scripts/audit/scopes.tsv`——域册（10 域：探测/演习/风控哨戒/账本/
   生命周期/饥饿/评估/唤知脚本/部署/数据桥）,每域 paths+不变量提示+
   KB 召回词；最久未审者先（ops_event seat=审计机 event=唤起 note
   `scope=<name>` 为审计史）。
2. `scripts/audit/dispatch.sh`——日拍（`o-audit.timer` 03:30）；单飞闸
   `o-audit-*`；跨机锁 advisory 7970 同唤知机形态；spawn
   `run.sh`（`COG_ROLE=audit`,会话目录/席名/心跳键/败迹 seat 全隔离）。
3. `scripts/audit/runbook.md`——审计会话规格：三维度扫描法+**证据闸三级**
   （RED→升件 / 造不出 RED→审计疑点 / 已证无误→覆盖面）+收口度量。
4. 唤知 runbook「审计」档——修理侧契约：先看 RED 红→修→GREEN→merge,
   **修复 commit 必引 升件#**；命题假→销+删支。
5. 探针：`audit_spawn_fail`（审计机败迹 2h≥2）/`audit_stall`（审计席 48h
   零产出）——臂自身的死也要被看见（当日教训：环死无声）。
6. 度量 `scripts/audit/foundby.sh`——近 N 天 `坑处置:` 修复提交中引
   `升件#` 的占比=机发现占比。**不设手工标签**（手工标签=「知道但不
   消费」的失败形态）；派生口径零成本不可作弊。

**铁律：**
- 审计会话**不修**（paths 下非测试文件零改动；不 merge/不 push master）。
- 无 RED 不升件。疑点行不唤修理会话。
- 升件 note 六件齐（维度/位置/根因/影响/RED/修法）——修理会话零猜测进场。

## 连锁影响

- 度量读数是本决策的存废判据：若 30 天后机发现占比仍≈0（审计升件
  零或全被销）,审计臂即为无效件,回本档改 runbook 或撤臂,不许静默
  空转（commercial_stall 同律：转而不出水=信号）。
- 每个被确认修复的审计缺陷类,修理会话须评估「能否机械化」并落闸/测试
  ——审计臂的目标是让自己的发现面逐渐被机械闸接管（棘轮）。
- 跨机第二审计节点暂不装（当日 env 漂教训：单节点跑通一周再扩）。
- 诚实边界：审计质量上限=模型×域提示×KB 判例密度。它能抓「两处不一」
  与「该在不在」,对「从未被踩的径里的算错」仍只能靠**强制行使**
  （演习臂）+审计会话主动为未测径写测试——后者写进 runbook 维度 C,
  但不承诺覆盖率。
