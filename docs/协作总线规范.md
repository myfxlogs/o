# 协作总线规范（mbus）

> 立规：管理席 @ 2026-10-29（业主令『树形授权+总线通信』——『信』面承建）
> 实现：`/opt/meta/mbus.sh`（meta 仓）｜邮箱：`/opt/meta/mail/<席>/{inbox,acked}`
> 席位：`MANAGE`（管理）/ `DM`（决策）/ `Dev`（施工）/ `OWNER`（业主）

## 0. 为什么是总线

树形权序管**权**（谁向谁汇报、谁裁决谁），总线管**信**（一切指令与回报的载体）。
链式 TUI 传信的两大死穴（2026-10-29 实证）：收件席 busy 时 `send-keys`+Enter
被静默吞掉（键入≠投递）；无回执（投没投到、读没读到全靠猜）。总线对策：
**发令=原子投文件**（tmp+mv，永不受对方忙闲影响）；**消费=ack 自动回执**；
**滞留=监理告警**。两段确认从纪律变成机器强制。

## 1. 报文格式

```
%%MB v1
id: 20261029-164437-MANAGE-1        ← 发出时刻-发送席-全总线递增序号
from: MANAGE
to: DM
type: directive|report|receipt|notice
ref: <被回执/被回复的件 id，无则空>
ts: 2026-10-29 16:44:37
---
正文（纯文本，多行）
```

- **directive**：下行指令（管理→DM→Dev）。收件席消费后必 ack。
- **report**：上行回报（Dev→DM→MANAGE）。工作结果的常规载体。
- **receipt**：ack 自动生成，回发送方——消费确认的机器形态。
- **notice**：知会件，不需 ack。

## 2. 操作（全席通用）

```bash
/opt/meta/mbus.sh send <to> <type> [ref] <text 或 -（stdin）>   # 发（MBUS_FROM=席号）
/opt/meta/mbus.sh list <to>                                     # 收件箱
/opt/meta/mbus.sh show <to> <id>                                # 看件
/opt/meta/mbus.sh ack <to> <id> [注]                            # 消费+自动回执
/opt/meta/mbus.sh check                                         # 监理巡检（滞留告警）
```

## 3. 纪律（harness 无关，全席约束）

1. **件是真相**：指令/回报以箱内件为准；TUI 轻叩（nudge）只是门铃，叩不响不影响投递效力。
2. **两段确认**（2026-10-29 管理令，AGENTS.md 同源）：发出方核 inbox 落件=**投递确认**；
   收到 `receipt` 回执=**消费确认**。双确认前，交接未完成，发出方不得转下一事项。
3. **消费时限**：directive/report 30min 内 ack；超时由监理（`check`）告警，收件席催办自清。
4. **回报链**：Dev→DM→MANAGE，逐级汇报逐级核阅；异常（阻塞/驳回/熔断/指令超时未消费）
   **即报不等节拍**；平常按事件回报（收口/裁决），不事事刷屏。
5. **心跳兜底**：总线长期无 traffic ≠ 一切正常——各席里程碑自报（report.sh）照旧并行；
   relay 日志仍是活动面权威源（查席纪律，AGENTS.md）。

## 4. 与既有轨道的关系

| 轨道 | 管什么 | 变不变 |
|---|---|---|
| mbus 总线 | 席位间指令/回报/回执（权序面通信） | **新设** |
| devin-relay 环 | DM↔Dev 派单/收口/审计标记自动化 | 照旧并行，渐迁 |
| report.sh | 席位里程碑自报→业主飞书 | 照旧并行 |
| AGENTS.md 两段确认条 | 纪律法典 | 已入编（同日） |

## 5. 冒烟实证（2026-10-29）

send→list→ack→receipt 全链通：`MANAGE→OWNER` notice 落箱；`DM→MANAGE` report
ack 后自动回执 `MANAGE→DM` receipt 落 DM 箱，`receipt.log` 双行留痕。

## 6. 事件泵 mbusd（2026-10-29 增——业主令『事件驱动+gRPC 流，不用定时任务/轮询』）

- **真相层不变**：文件邮箱仍是唯一真相；`mbusd` 只是事件泵——inotify 感知落件，
  gRPC/Connect server-stream（`Mbus/Subscribe(seat)`）实时推送 `MAIL_NEW /
  MAIL_ACKED / STALE / SEAT_LIVE / SEAT_SILENT` 事件。daemon 死亡=退化 pull，
  **无单点**（systemd user 常驻，Restart=always）。
- **滞留监理事件化**：投件即起单发定时器（30min），到点报 STALE——无周期扫描；
  `mbus.sh check` 仅作 daemon 死亡时的手动兜底。
- **心跳面**：`mbus.sh hb [席]`（send/ack/report 自报轨自动发射）触碰
  `/opt/meta/mail/.hb/<席>`；静默 2h=单发 `SEAT_SILENT` 告警，活动即复位。
  心跳证**进程级在线**，消费回执证**任务级在线**，两信号互补——查席以心跳为
  先，tmux+relay 日志降为兜底。
- **订阅端**：`mbuslisten <席|ALL>`（断线退避重连）。跨项目/跨主机复用即订阅
  此流；跨主机暴露前须先补认证面（现仅绑 127.0.0.1）。
