# T-0332 返修①——两死表取数径与静默吞错显形

驳回由（决策席无头拍 devin @ 2026-11-04）：收口件 @499936f4（分支
t/0332-gauges）全件合钦定形——谱系册/量表册/tick 拍/模板伴生段
俱在，范围票面内零越界。唯首批五量表两死一吞，锚「五座各有触阈/
空跑实录」不达：

- **违①（两死表）**：拍壳唯一取数径 `FIN_PG_DSN`=roster_rw，对
  `fin_proposal`/`fin_execution`/`fin_position` 三表 **SELECT 零权**
  （relacl 亲证：fin_execution 仅 review_rw 可读；o_fin_ro 持
  fin_proposal/fin_position 亦不及 fin_execution）。决策席亲跑五表：
  `armed_aging`→permission denied、`arm_zero_output`→permission
  denied、`escalation_aged`=0 绿、`heartbeat_dead`=0 绿、
  `branch_cemetery`=383>300 触（滞回首日 hit 在案）。
- **违②（静默吞错）**：tick 取数 `psql ... 2>/dev/null | head -1`
  →权限错 v 空→`continue` 静默跳——**永不可触且零痕迹**。此正是
  票面八类谱系自列「静默吞错/缺席」病灶：巡检面自身犯禁。
  取数失败须显形——psql rc/stderr 不可全吞；失败表记入状态件或
  心跳 note 带 fail 表名（缺席≠绿灯）。
- **违③（回填实录虚位）**：锚要求五表各出触阈/空跑实录，回填仅
  branch_cemetery 一触+「空跑零升件」泛词——两死表既无值亦无
  「绿灯在案」注，报错被吞成绿灯假象。

## 修向（钦定约束内施工裁）

1. 取数径：gauges.tsv 增 `sql_ro` 型走 `FIN_PG_RO_DSN`（o_fin_ro
   持 fin_proposal/fin_position SELECT 在案）；`arm_zero_output`
   如需留 fin_execution——走 o_fin_ro GRANT 补授（T-0322 返修①
   fin_condition_gap 同径先例：迁移链落 grant+check_migrations 过）
   或换可读口径——二择落票注取舍。
2. 显形：取数失败（rc≠0 或 stderr 非空）不得 v 空即 continue——
   记入 `$ST/<name>.fetch_error` 或 hb note 携带；该失败自身即
   缺席类升件素材。
3. gauges.tsv 头注宣称 `sql_md` 型未实现——实现或删注（头注即
   契约，虚称=虚报类）。
4. 返修收口：**五表逐表实测值随票**（sql_ro 型各出行+值），
   check_all 绿戳随收口；同支 t/0332-gauges 续提。
