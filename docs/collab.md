# O 多 Agent 协作协议

> `[角色:决策]` 立于 2026-10-23。修订走任务单流程。依据见 `docs/decisions/D-0001-multi-agent-collab.md`。

## 0. 为什么是这个机制

多 Agent 同仓有三大事故源：

1. **无持久工作队列**——新进场 Agent 看不见「该做什么、谁在做」
2. **意图与实现脱节**——施工产出偏离决策原意，且无验收判据可对
3. **无审计痕**——事后无法回答「谁定的、为什么」

对策 = **任务单为唯一工作入口 + 分支隔离施工 + 角色标签全程留痕**。

- 纯对话标签（只在 commit 加前缀）解决不了 ①②
- 纯分支制解决不了 ②③——分支只表「在做什么」，不表「该做什么」与「怎么算做完」

## 1. 角色

### `[角色:决策]`

- 立任务单（`docs/tasks/`）：写清背景 / 目标 / 验收标准 / 涉及面
- 审批：`草案 → 已批`，审批时检查「涉及面」与在途单不撞
- 验收：`待验 → 完成` 或打回，对照验收标准逐条核——翻完成同拍执行 `~/bin/report.sh 完成 T-NNNN`（落 ops_event `完成` 行：管道退场钦定信号，T-0283 粘滞退场径）
- 写决策记录（`docs/decisions/`）：方向级选择留档防再议
- 禁：直接写实现代码。typo / 文档级可顺手修，commit 仍标 `[角色:决策]`

### `[角色:施工]`

- 领单 → 实现 → 自测 → 提交 → 回填任务单「结果」段
- 禁：超单施工。发现单有错漏**不改单**——改状态为 `挂起` 并写阻塞说明，交回决策

- 施工产出必须由**另一 session** 的决策角色验收

    - **直办**：`docs/**` 纯文档件（README/KB 条目/票文/提示词/清单类）COS 在岗时可不经施工席直接落 `/opt/o` master——`[角色:COS][T-NNNN]` commit + check_all 绿戳对口，同 commit 票面记 `领取=cos-direct@ts` 并翻 `待验`；决策席下拍照样逐锚裁决——**免的是施工环节不是验收**。禁做：代码/迁移/proto/app_config/脚本/部署面——碰即越权，按返修计次。

## 2. 任务单

- 文件：`docs/tasks/T-NNNN-短横线slug.md`，编号顺序取用、**不回收**
- 模板：`docs/tasks/TEMPLATE.md`
- 查队列：`grep -l '状态.*已批' docs/tasks/T-*.md`
- **立票开放（T-0322 件C——「立票」拆两层：提案入口全开放/批准入口不开放）**：
  - **草案（draft）任角色可立**——任意角色按模板立草案单进 `docs/tasks/`（撞号让号重编、编号不回收照旧）；
  - **`草案→已批` 批准闸归 COS 席**（例行代理件持业主授权直批——§1 席面分家写面判据：草案→已批只属 COS 交互形态）；提案席不得自批，「能提案」≠「能批准」；
  - 票面「立项」字段记**实际立票席+出处**（业主令/决策立/他席代笔——出处可追溯），代立单如实在字段写明。

### 生命周期

```
草案(draft) → 已批(approved) → 施工中(doing) → 待验(review) → 完成(done)
                 ↓                    ↓
              作废(void)           挂起(blocked)
```

| 迁移 | 动作方 | 要求 |
|---|---|---|
| 草案→已批 | COS（例行代理件授权） | 涉及面与在途单排他检查通过 |
| 已批→施工中 | 施工 | 走 §3 领单流程 |
| 施工中→待验 | 施工 | 自测过，结果段已回填，分支已推送 |
| 待验→完成 | 决策 | 逐条核对验收标准，合回 master |
| 待验→施工中 | 决策 | 打回，写明差哪几条 |
| 任意→挂起/作废 | 任意角色 | 写明原因；挂起单由决策处置 |

### 关键字段（详见模板）

- **验收标准**：可逐条打勾的客观判据，是「完成」的唯一裁判
- **涉及面**：预计改动的路径/模块——审批排他、施工估撞车都靠它
- **范围外**：明示不做什么，防施工蔓延

## 3. 领单与防双抢

施工 Agent 进仓（**全程不碰部署树 `/opt/o`**，§9）：

1. `git fetch origin`（任意工作目录）
2. 找 `状态=已批` 且 `领取` 为空的单（master 或远端票内为准）
3. **建工作树即建支**：`git worktree add /opt/o-wt/tNNNN -b t/NNNN-slug origin/master`
4. 在**自己分支上**翻单：`状态→施工中`、填 `领取`（session 标识 @ 时间）
5. **立即** commit + push 分支：`[角色:施工][T-NNNN] 领单`——**分支 push 成功=锁单**；远端已有 `t/NNNN-*` 支=有人先抢，换单

认领即锁，**锁凭据=分支+分支上的翻单提交**，以远端分支存在性为准，无争议空间。master 上的票面状态滞至合并时由决策席统一翻（施工中→待验在施工分支推进，不影响锁）。

session 标识自定（如 `devin-a1b2`），全仓唯一即可，建议加可辨来源。

### 出指令规程（单行指针——nox D-664 继承）

- 派发提示词=**单行指针**：`[角色:X] T-NNNN <一句话目标>（读票面全文[+skills/<venue-域>]）`——上下文全压票面，禁把施工细节塞进提示词。
- 细节（码面勘查/边界钉/验收锚）一律回填任务单文件；提示词多行=细节溜出票面的信号——发前归位再发。

## 4. 分支与提交

- 施工分支：`t/NNNN-slug`，一单一支
- 验收通过由决策角色合回 master
- commit 格式：`[角色:X][T-NNNN] 摘要`；非任务单工作（协议修订等）：`[角色:X] 摘要`
- 决策角色的单外动作（审批、验收合并）commit 同样标 `[角色:决策]`

## 5. 冲突处理

- 施工发现任务单事实错误/不足 → `挂起` + 阻塞说明，不自作主张扩单
- 两单涉及面相撞 → 决策审批环节应拦下；漏拦的，后到单挂起等前单完成
- 协议本身修订 → 走任务单流程，由决策角色执行

## 6. 决策记录

- `docs/decisions/D-NNNN-slug.md`，仅决策角色写，编号不复用
- 记：背景、选项、取舍理由、**淘汰项及弃因**（沿用 README 淘汰谱传统）
- 决策档为终审：后续 Agent 读档知「此事已议，勿再开题」；要翻案须立新档写明推翻理由

## 7. 交付自检（两时点强制：方案成形时一遍 + 交付/送验前再一遍）

通用核 A–I（自 nox 总纲 §4 继承，D-591+D-590+D-651-b，全席适用）：

| 项 | 核 |
|---|---|
| A 架构 | 复用现有、无逆向依赖；有更简等价解存在却未用=败 |
| B 实现 | 第一性原理直击问题本质，无多余间接层 |
| C 洁净 | 无重复/死码/TODO/调试残渣 |
| D 正确 | 边界/nil/竞态/错误路径——对抗性测试：删一关键行必有测试红 |
| E 合规 | 总纲 §1 定位 + `工程纪律.md` + `架构约束.md` 逐条 |
| F 文档 | 任务单/D 档/模块页同步且与码一致 |
| G 验收锚对账 | 每条验收标准一行「锚=PASS+证据｜未达+缺口」；零锚票明写「无锚」；机检 exit code 贴出 |
| H 生产现实对拍 | 票面触生产数字/ID/映射须亲证——附可复现出处，禁听闻写常量映射 |
| I 展示值与判定取值同源对拍 | 卡/提案展示数与执行读的物同源——「快照与判定异源」=退回项 |

- 自检=过程非报告：不等业主/复审催；对账表是痕不是替身
- 复审/决策席同责：裁决引生产/码事实须附亲证出处，否则标「未亲证」
- 施工单专用加项：commit 前缀正确、分支名合规、任务单「结果回填」已写（实现摘要/测试证据/偏离说明）、无范围外改动（有→结果段说明交决策裁）

## 8. 施工结束语（交付必填模板——缺件=半交付，退回计次）

施工提交验收前必须输出以下固定格式（自 nox 收口机械门继承）：

```
分支: t/NNNN-slug（已推送=已交付；未推送=未交付）
验收锚对账:
  - <验收标准①>: PASS（证据:<文件/命令/输出锚>）| 未达（缺口:<差什么>）
  - <验收标准②>: ...
机检: build✓ vet✓ gofmt✓ test✓ 经验库 schema✓ env✓（逐闸列结果，红=禁交付）
自检 A–I: <逐项一句；有弃项须说原因>
涉及面: <实际触碰的文件/目录>
范围外确认: <声明未越单做的面>
移交: 决策席
[施工收口:T-NNNN] @<commit hash>
```

`[施工收口:T-NNNN] @hash` **固定为收口尾行**（复制转发件）——缺席即半交付（D-四件机械门：对账/机检/移交行/状态翻转，缺一不计交付）。

## 9. 工作面隔离（双席并行防占位——2026-10-23 实证立）

- **`/opt/o` 部署树=master 常检，决策席专用面**：只许台账 docs 提交（D-651 白名单面）+验收合并。施工席**禁在部署树检出分支/编辑/提交**——违者 D-651 闸拦+计次。
- **施工工作面=自己的 worktree**：`git worktree add /opt/o-wt/<票> -b t/<票>`，一单一树；票毕 `worktree remove`+删支。
- 多席并行零互踩的前提=各守各树；`.git` 级竞态（index.lock/HEAD 漂移）一旦出现即说明有人在部署树动手。
- 检出纪律自查：任何席在 /opt/o 见到 `git branch --show-current` 非 master = 先报决策席，禁顺手切回（可能正有合并/领单进行中）。

## 10. 会话尾（退仓纪律——nox D-592 精神继承版，T-0049 立）

任何角色 session 收尾前，三步机械门——缺一=半交付：

1. **实质对话落 `docs/handoff/dialogue.md`**——只录决策/探问/转向/授权级内容（谁授权了什么、为什么改方向、裁了什么争议）；纯执行回执不录。session 死≠事实死——对话里的授权与裁断不落文件，对项目等于没发生。
2. **事实归位扫描**——本 session 产生的项目事实各归其位：坑→`docs/工程经验库/条目/`（**有坑即写条目+`tools/kbgen gen` 重建索引——业主令 10-25 废待归纳层，排队=下个 session 盲区**）；venue 面新证→`skills/` 同票修订（在用中证错必修）；方向裁断→`docs/decisions/`。**私有记忆不得独存项目事实**。
3. **提交即推送**——收工时 `git status` 净 + `git log @{u}..` 空；本地领先未推送=断链风险。

## 11. SG 轮换 SOP（T-0054 立；D-0035/T-0217 重铸——多席撞车实证后部署唯一径固化）

**钦定径=`scripts/deploy_image.sh` 一条令**（出处闸+SG 部署锁+SHA tag 留痕+健康闸全机内化；手工 build/save/up 绕锁=违例，回滚/热补走 `O_DEPLOY_ALLOW_UNPUSHED=1` 显式放行）：

```bash
scripts/deploy_image.sh          # 本机构建+船运+锁内 up+健康闸+产地尾拍
```

脚本内断言（每步禁「Started」即当成功，与旧四步同构）：

1. **出处闸**：脏树拒；HEAD 不在 origin/master 拒（堵陈码盖新码——多席撞车病灶机内化）。
2. **SG 部署锁**：`ssh mkdir /opt/o/.deploy-lock` 原子互斥，持锁写 holder=seat/sha/ts/token；陈锁>30min 或 `O_DEPLOY_FORCE=1` 抢（WARN 先打），EXIT trap token 匹配释锁。
3. **SHA tag 留痕**：`o-core:<sha12>` 主 tag+`o-core:latest` 同层别名双 ref 齐运——容器 `.Config.Image` 自报所跑源码 commit（旧「latest 逐字比对」步语义升级：产地在 tag 字面，不再靠镜像 ID 对拍）。
4. **健康闸**：尾拍 `docker inspect .Config.Image` 印产地+90s 轮询 `.State.Health.Status`——不转 healthy 即 die 禁收工。

人工排障对照（非部署径，仅查证用）：`.Config.Image`=o-core:<sha> 应对 `git rev-parse --short=12 HEAD`；`cat /opt/o/.deploy-lock/holder` 查持锁席。
