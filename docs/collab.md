# 现行法（纪元3——全文可按此读）

## 1. 决策档（docs/decisions/）

- `docs/decisions/D-NNNN-slug.md`，编号不复用；记背景、选项、取舍理由、
  **淘决项及弃因**（沿用 README 淘汰谱传统）。
- 决策档为终审：后续 Agent 读档知「此事已议，勿再开题」；要翻案须立新档
  写明推翻理由。方向级选择防再议——D-0045 起新章。

## 2. 交付自检（两时点强制：方案成形时一遍 + 交付/送验前再一遍）

通用核 A–I（自 nox 总纲 §4 继承，D-591+D-590+D-651-b，全席适用）：

| 项 | 核 |
|---|---|
| A 架构 | 复用现有、无逆向依赖；有更简等价解存在却未用=败 |
| B 实现 | 第一性原理直击问题本质，无多余间接层 |
| C 洁净 | 无重复/死码/TODO/调试残渣 |
| D 正确 | 边界/nil/竞态/错误路径——对抗性测试：删一关键行必有测试红 |
| E 合规 | 总纲 §1 定位 + `工程纪律.md` + `架构约束.md` 逐条 |
| F 文档 | 任务单/D 档/模块页同步且与码一致 |
| G 验收锚对账 | 每条验收标准一行「锚=PASS+证据｜未达+缺口」；零锚票明写「无锚」；机检 exit code 贴出 |
| H 生产现实对拍 | 票面触生产数字/ID/映射须亲证——附可复现出处，禁听闻写常量映射 |
| I 展示值与判定取值同源对拍 | 卡/提案展示数与执行读的物同源——「快照与判定异源」=退回项 |

- 自检=过程非报告：不等业主/复审催；对账表是痕不是替身。
- 复审/决策方同责：裁决引生产/码事实须附亲证出处，否则标「未亲证」。
- 修复类件先红桩（工程纪律 §3/T-0388）：验收首锚=病灶存在断言
  （修前红）+同断言修后绿——收口无先红断言=驳回条件；豁免只限
  新功能/纯文档件注明。

## 3. 工作面隔离（防占位——纪元3 沿用）

- **`/opt/o` 部署树=master 常检**：只许 pull/merge/deploy 与账本 docs
  提交。码面改动一律 worktree——违者闸拦+计次。
- **工作面=自己的 worktree**：`git worktree add /opt/o-wt/<名>`，
  用毕 `git worktree remove`+删支（wt_gc 人工径——纪元3 起无机扫件，
  对账 `git worktree list` 逐树判 merged/脏/活）。
- 新 wt 先 bootstrap：`bash scripts/bootstrap_worktree.sh`（buf 正径再生
  gen；缺席降级 rsync 部署树快照——明示非静默）。
- `.git` 级竞态（index.lock/HEAD 漂移）出现即说明有人在部署树动手——
  先报再处，禁顺手切回。
- 检出纪律自查：任何会话在 /opt/o 见到 `git branch --show-current` 非
  master = 先报，禁顺手切回（可能正有合并/领单进行中）。

## 4. 会话尾（退仓纪律——三步机械门，缺一=半交付）

1. **事实归位扫描**——本 session 产生的项目事实各归其位：
   坑→`docs/工程经验库/条目/`（**有坑即写条目+`go run ./tools/kbgen gen`
   重建索引——业主令 10-25 废待归纳层，排队=下个 session 盲区**）；
   venue 面新证→`skills/` 同票修订（在用中证错必修）；
   方向裁断→`docs/decisions/`。**私有记忆不得独存项目事实**。
2. **提交即推送**——收工时 `git status` 净 + `git log @{u}..` 空；
   本地领先未推送=断链风险。
3. **交付自检 A–I + 证据对账**——见 §2；交付语含分支/验收锚对账/
   机检/涉及面/范围外确认/移交行（纪元3 收口语形见唤知会话 runbook④
   与各席交付惯例，固定尾行格式以发单方要求为准）。

## 5. 部署 SOP（SG 轮换——D-0035/T-0217 重铸，纪元3 沿用）

**钦定径=`scripts/deploy_image.sh` 一条令**（出处闸+SG 部署锁+SHA tag
留痕+健康闸全机内化；手工 build/save/up 绕锁=违例，回滚/热补走
`O_DEPLOY_ALLOW_UNPUSHED=1` 显式放行）：

```bash
scripts/deploy_image.sh          # 本机构建+船运+锁内 up+健康闸+产地尾拍
```

脚本内断言（每步禁「Started」即当成功）：

1. **出处闸**：脏树拒；HEAD 不在 origin/master 拒（堵陈码盖新码）。
2. **SG 部署锁**：`ssh mkdir /opt/o/.deploy-lock` 原子互斥，持锁写
   holder=seat/sha/ts/token；陈锁>30min 或 `O_DEPLOY_FORCE=1` 抢
   （WARN 先打），EXIT trap token 匹配释锁。
3. **SHA tag 留痕**：`o-core:<sha12>` 主 tag+`o-core:latest` 同层别名
   双 ref 齐运——容器 `.Config.Image` 自报所跑源码 commit。
4. **健康闸**：尾拍 `docker inspect .Config.Image` 印产地+90s 轮询
   `.State.Health.Status`——不转 healthy 即 die 禁收工。

**两半部署制（T-0425）**：部署面二分各持基线各判各发——**镜像面**=
入 o-core 镜像路径→`deploy_image.sh`；**OCI 二进制面**=OCI 构建源
（谱系正本 `deploy/deploy-faces.tsv`——镜像面∧¬镜像专属面，未列名=
面不可判保守按双发）→同窗发 `scripts/deploy_oci.sh`（臂级谱系自检
幂等：diff 证空即跳零烧）。**一面应发而未发/发败→必落 ops_event
「半截部署」升件**——禁静默半部署。

人工排障对照（非部署径，仅查证用）：`.Config.Image`=o-core:<sha> 应对
`git rev-parse --short=12 HEAD`；`cat /opt/o/.deploy-lock/holder` 查持锁席。

## 6. 数据流正本

`docs/数据流.md` = 系统数据流唯一真源。改动链路的件同 commit 更新；
方向纠偏/架构核对/施工对位先读此图。

# 纪元2 史证附录（勿作流程依据——席位/票/相位机制已裁撤）

> 以下为纪元2 协作协议原文存档。判词锚=D-0045 覆盖条+AGENTS.md 家电律。

## 史证 §0. 为什么是这个机制（纪元2）

多 Agent 同仓有三大事故源：

1. **无持久工作队列**——新进场 Agent 看不见「该做什么、谁在做」
2. **意图与实现脱节**——施工产出偏离决策原意，且无验收判据可对
3. **无审计痕**——事后无法回答「谁定的、为什么」

对策 = **任务单为唯一工作入口 + 分支隔离施工 + 角色标签全程留痕**。

- 纯对话标签（只在 commit 加前缀）解决不了 ①②
- 纯分支制解决不了 ②③——分支只表「在做什么」，不表「该做什么」与「怎么算做完」

## 史证 §1. 角色（纪元2——席位拍全裁撤）

### `[角色:决策]`（纪元2=CTO 席/无头 o-decision-seat）

- 立任务单（`docs/tasks/`）：写清背景 / 目标 / 验收标准 / 涉及面
- 审批：`草案 → 已批`，审批时检查「涉及面」与在途单不撞
- 验收：`待验 → 完成` 或打回，对照验收标准逐条核——翻完成同拍执行
  `~/bin/report.sh 完成 T-NNNN`（落 ops_event `完成` 行：管道退场
  钦定信号，T-0283 粘滞退场径）
- 写决策记录（`docs/decisions/`）：方向级选择留档防再议
- 禁：直接写实现代码。typo / 文档级可顺手修，commit 仍标 `[角色:决策]`

### `[角色:施工]`（纪元2=施工席/o-worker 无头 run）

- 领单 → 实现 → 自测 → 提交 → 回填任务单「结果」段
- 禁：超单施工。发现单有错漏**不改单**——改状态为 `挂起` 并写阻塞
  说明，交回决策

### 生命周期（纪元2）

```
草案(draft) → 已批(approved) → 施工中(doing) → 待验(review) → 完成(done)
                 ↓                    ↓
              作废(void)           挂起(blocked)
```

| 迁移 | 动作方 | 要求 |
|---|---|---|
| 草案→已批 | COS（例行代理件授权） | 涉及面与在途单排他检查通过 |
| 已批→施工中 | 施工 | 走 §3 领单流程 |
| 施工中→待验 | 施工 | 自测过，结果段已回填，分支已推送 |
| 待验→完成 | 决策 | 逐条核对验收标准，合回 master |
| 待验→施工中 | 决策 | 打回，写明差哪几条 |
| 任意→挂起/作废 | 任意角色 | 写明原因；挂起单由决策处置 |

### 关键字段（纪元2，详见模板）

- **验收标准**：可逐条打勾的客观判据，是「完成」的唯一裁判
- **修复类票先红桩**（工程纪律 §3/T-0388）：验收标准首锚=病灶存在断言
  （修前红）+同断言修后绿——收口无先红断言=驳回条件；豁免只限
  新功能/纯文档票面注明
- **涉及面/范围**：预计改动的路径/模块——审批排他、施工估撞车都靠它；
  T-0413 派单依赖闸按「范围」节明确路径/目录清单+分支 diff 机械对拍，
  缺清单=不可判排队
- **范围外**：明示不做什么，防施工蔓延

## 史证 §3. 领单与防双抢（纪元2）

施工 Agent 进仓（**全程不碰部署树 `/opt/o`**，§9）：

1. `git fetch origin`（任意工作目录）
2. 找 `状态=已批` 且 `领取` 为空的单（master 或远端票内为准）
3. **建工作树即建支**：`git worktree add /opt/o-wt/tNNNN -b t/NNNN-slug origin/master`
4. 在**自己分支上**翻单：`状态→施工中`、填 `领取`（session 标识 @ 时间）
5. **立即** commit + push 分支：`[角色:施工][T-NNNN] 领单`——**分支
   push 成功=锁单**；远端已有 `t/NNNN-*` 支=有人先抢，换单

认领即锁，**锁凭据=分支+分支上的翻单提交**，以远端分支存在性为准，
无争议空间。master 上的票面状态滞至合并时由决策席统一翻（施工中→待验
在施工分支推进，不影响锁）。

session 标识自定（如 `devin-a1b2`），全仓唯一即可，建议加可辨来源。
