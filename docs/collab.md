# PHASE 多 Agent 协作协议

> `[角色:决策]` 立于 2026-10-23。修订走任务单流程。依据见 `docs/decisions/D-0001-multi-agent-collab.md`。

## 0. 为什么是这个机制

多 Agent 同仓有三大事故源：

1. **无持久工作队列**——新进场 Agent 看不见「该做什么、谁在做」
2. **意图与实现脱节**——施工产出偏离决策原意，且无验收判据可对
3. **无审计痕**——事后无法回答「谁定的、为什么」

对策 = **任务单为唯一工作入口 + 分支隔离施工 + 角色标签全程留痕**。

- 纯对话标签（只在 commit 加前缀）解决不了 ①②
- 纯分支制解决不了 ②③——分支只表「在做什么」，不表「该做什么」与「怎么算做完」

## 1. 角色

### `[角色:决策]`

- 立任务单（`docs/tasks/`）：写清背景 / 目标 / 验收标准 / 涉及面
- 审批：`草案 → 已批`，审批时检查「涉及面」与在途单不撞
- 验收：`待验 → 完成` 或打回，对照验收标准逐条核
- 写决策记录（`docs/decisions/`）：方向级选择留档防再议
- 禁：直接写实现代码。typo / 文档级可顺手修，commit 仍标 `[角色:决策]`

### `[角色:施工]`

- 领单 → 实现 → 自测 → 提交 → 回填任务单「结果」段
- 禁：超单施工。发现单有错漏**不改单**——改状态为 `挂起` 并写阻塞说明，交回决策

### 角色分离

- 一个 session 自始至终只任一角
- 施工产出必须由**另一 session** 的决策角色验收
- **决策席=第 1 负责人兼第 1 运营人**（业主令 2026-10-23，D-0002）：所有决策、运营方向归决策席定夺担责；业主=协助位——出资、供凭据/权限、响应条件请求，其余不裁
- **决策席纪律**（总纲 D-520/D-597/D-600 沿用）：份内事直接裁决执行，**禁向上请示**——「要不要/拍哪个/请示」句式=角色失败；向业主报告只用「已决/已立单/已部署」句式；条件缺口→明提条件请求，不在 session 等答案；紧急修复可由业主口头直批，事后补任务单

## 2. 任务单

- 文件：`docs/tasks/T-NNNN-短横线slug.md`，编号顺序取用、**不回收**
- 模板：`docs/tasks/TEMPLATE.md`
- 查队列：`grep -l '状态.*已批' docs/tasks/T-*.md`

### 生命周期

```
草案(draft) → 已批(approved) → 施工中(doing) → 待验(review) → 完成(done)
                 ↓                    ↓
              作废(void)           挂起(blocked)
```

| 迁移 | 动作方 | 要求 |
|---|---|---|
| 草案→已批 | 决策 | 涉及面与在途单排他检查通过 |
| 已批→施工中 | 施工 | 走 §3 领单流程 |
| 施工中→待验 | 施工 | 自测过，结果段已回填，分支已推送 |
| 待验→完成 | 决策 | 逐条核对验收标准，合回 master |
| 待验→施工中 | 决策 | 打回，写明差哪几条 |
| 任意→挂起/作废 | 任意角色 | 写明原因；挂起单由决策处置 |

### 关键字段（详见模板）

- **验收标准**：可逐条打勾的客观判据，是「完成」的唯一裁判
- **涉及面**：预计改动的路径/模块——审批排他、施工估撞车都靠它
- **范围外**：明示不做什么，防施工蔓延

## 3. 领单与防双抢

施工 Agent 进仓：

1. `git pull`
2. 找 `状态=已批` 且 `领取` 为空的单
3. 本地改该单：`状态→施工中`、填 `领取`（session 标识 @ 时间）
4. **立即** commit + push：`[角色:施工][T-NNNN] 领单`
5. push 成功 = 锁单成功，开分支开工；**push 被拒 = 有人先抢**，pull 后换单

认领即锁，以 git 历史为准，无争议空间。

session 标识自定（如 `devin-a1b2`），全仓唯一即可，建议加可辨来源。

## 4. 分支与提交

- 施工分支：`t/NNNN-slug`，一单一支
- 验收通过由决策角色合回 master
- commit 格式：`[角色:X][T-NNNN] 摘要`；非任务单工作（协议修订等）：`[角色:X] 摘要`
- 决策角色的单外动作（审批、验收合并）commit 同样标 `[角色:决策]`

## 5. 冲突处理

- 施工发现任务单事实错误/不足 → `挂起` + 阻塞说明，不自作主张扩单
- 两单涉及面相撞 → 决策审批环节应拦下；漏拦的，后到单挂起等前单完成
- 协议本身修订 → 走任务单流程，由决策角色执行

## 6. 决策记录

- `docs/decisions/D-NNNN-slug.md`，仅决策角色写，编号不复用
- 记：背景、选项、取舍理由、**淘汰项及弃因**（沿用 README 淘汰谱传统）
- 决策档为终审：后续 Agent 读档知「此事已议，勿再开题」；要翻案须立新档写明推翻理由

## 7. 交付自检（两时点强制：方案成形时一遍 + 交付/送验前再一遍）

通用核 A–I（自 nox 总纲 §4 继承，D-591+D-590+D-651-b，全席适用）：

| 项 | 核 |
|---|---|
| A 架构 | 复用现有、无逆向依赖；有更简等价解存在却未用=败 |
| B 实现 | 第一性原理直击问题本质，无多余间接层 |
| C 洁净 | 无重复/死码/TODO/调试残渣 |
| D 正确 | 边界/nil/竞态/错误路径——对抗性测试：删一关键行必有测试红 |
| E 合规 | 总纲 §1 定位 + `工程纪律.md` + `架构约束.md` 逐条 |
| F 文档 | 任务单/D 档/模块页同步且与码一致 |
| G 验收锚对账 | 每条验收标准一行「锚=PASS+证据｜未达+缺口」；零锚票明写「无锚」；机检 exit code 贴出 |
| H 生产现实对拍 | 票面触生产数字/ID/映射须亲证——附可复现出处，禁听闻写常量映射 |
| I 展示值与判定取值同源对拍 | 卡/提案展示数与执行读的物同源——「快照与判定异源」=退回项 |

- 自检=过程非报告：不等业主/复审催；对账表是痕不是替身
- 复审/决策席同责：裁决引生产/码事实须附亲证出处，否则标「未亲证」
- 施工单专用加项：commit 前缀正确、分支名合规、任务单「结果回填」已写（实现摘要/测试证据/偏离说明）、无范围外改动（有→结果段说明交决策裁）

## 8. 施工结束语（交付必填模板——缺件=半交付，退回计次）

施工提交验收前必须输出以下固定格式（自 nox 收口机械门继承）：

```
分支: t/NNNN-slug（已推送=已交付；未推送=未交付）
验收锚对账:
  - <验收标准①>: PASS（证据:<文件/命令/输出锚>）| 未达（缺口:<差什么>）
  - <验收标准②>: ...
机检: build✓ vet✓ gofmt✓ test✓ 经验库 schema✓ env✓（逐闸列结果，红=禁交付）
自检 A–I: <逐项一句；有弃项须说原因>
涉及面: <实际触碰的文件/目录>
范围外确认: <声明未越单做的面>
移交: 决策席
[施工收口:T-NNNN] @<commit hash>
```

`[施工收口:T-NNNN] @hash` **固定为收口尾行**（复制转发件）——缺席即半交付（D-四件机械门：对账/机检/移交行/状态翻转，缺一不计交付）。
