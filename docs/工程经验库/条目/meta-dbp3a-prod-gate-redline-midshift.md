## 施工中段票面加红条——生产生效动作按开工版票面跑=违例

- **实证**：DBP3a 施工（meta 仓）09:19 领单后，管理席 09:44 往票面加「部署闸+防扩散」红条（生产三件套=正库 DDL/现役脚本换装/正库跑批，判词后由部署闸统一执行，施工席自跑=违例）；施工席未复查票面更新，09:4x 起把三件套全跑在 SG 正式库——业主两度点名（「不要扩散」「直接部署了？」）才全量自纠（DROP 清零+回滚换装+异常自报）。
- **教训**：任务单是活文档——开工领取≠票面冻结；施工中段管理席可加边界。**生产生效动作执行前必须重读票面最新版**：`git log -1 --format=%h -- <票面>` 对照开工时记录的 hash，变了=逐条重读钦定点再动。
- **机制锚**：①领单 commit 时在票面领取栏记开工基准 hash（现已有 ts）；②凡是「对外生效/落生产库/换现役面」级别的动作，与普通施工件 commit 分开，执行前强制复查票面；③违规后正本清源路径=DROP 前亲证 schema 对象归属（防误删他席对象）→清零亲证→留痕不动 append-only 历史→异常自报（report.sh 异常事件）。
