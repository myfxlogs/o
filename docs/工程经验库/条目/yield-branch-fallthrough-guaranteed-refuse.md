# 让位支真空洞（deploy_watch 实证）

**坑形**：守护/编排脚本里写「条件 X——让位（不推不升）」日志，却没有
`exit`/跳过——支尾坠回主流，执行一个**已知必败**的动作
（deploy_watch 尖未盖戳/push 败两支：日志说让位，流程坠到部署段，
deploy_image 出处闸对未推 HEAD 必拒 rc=1 → deploy_blocked 升件）。
每个 merge→戳→推窗必发一次，三周内三连（#9689/#10562/再燃）。

**判别**：升件销案词为「瞬态已愈」而**同型升件按节奏复发**——不是
懒判词也不是假愈，是触发器结构把「自伤噪音」当「病灶」。先查触发
链上有没有「宣告让位但没落 exit」的真空洞支。

**修法**：让位支补 `exit 0`（真让位），或把后续段包进 else。
验收=构出必拒场景跑脚本，确认零升件零必败调用。

**推广**：凡「前置闸拒→主流必败」的编排件，「让位/跳过」必须是控制
流事实不是日志措辞——日志给阅读者，exit 给机器。
