# 失败分支直落升件（deploy_watch 推败三连实证）

**坑形**：守护件「动作败→升件」一步写死，不先对拍败因可分性——
deploy_watch 尖盖戳后 `git push` 败即落 deploy_push_blocked，
而 mirror_push（独立 15min 拍）并行推同 sha 的撞窗=远端已含尖的
设计内瞬态。三周内三连（#9531 销「瞬态」→#10547→#11330），
stuck_esc#11331 判「宣称不实」如实——逐案判词为真≠结构死，
触发器不判败因可分性就必再产同型噪音。

**判别**：同型升件按节奏复发而每次销案词皆「瞬态/竞态」——
不是懒判词也不是假愈，是败分支缺「败后再核一次」：
重查条件是否已被并行善意动作治愈。

**修法**：败支先对拍（fetch+`merge-base --is-ancestor`）——
条件已愈=让位零升件；真败因=照升不误。验收=构出竞窗
（并行推同 sha），确认零升件。

**推广**：凡「败→升件」分支，升件前先问「败因可分性」——
并行善意动作能治愈的败不是信号。
