# 产出锚≠活性锚（calendar-feed 实证）

**坑形**：断流探针用「下游产出表的最后行龄」当 feed 活性证据，而
产出本身是**条件性**的（calendar 只在 min_impact=High 事件命中才
落 push 行）。上游活、产出设计态缺席的窗（老兵节零 high 事件
11-11 实测），探针按产出行龄判死必误发——条件缺席多久误报多久。

**判别**：升件面「feed 行龄超阈」而源头端点实测 200 活=先分因
「产出条件缺席」vs「拉取环死」。产出侧零行 ≠ 活性侧零拍——
两问不同，锚错即假。

**修法**：活性账与产出账分表——拉取环逐拍（含败拍/空拍）落
`md_calendar_pull(ok,events,err)`，探针锚 `max(ts)` 活性行龄；
产出表退回业务语义面（谁消费 push 谁管推件鲜度）。退避窗内
设计态不拉=不落行，行龄断=环真死。

**推广**：凡「条件性产出」的 feed（过滤/阈值/事件驱动），鲜度
探针锚活性不锚产出；新探针立项先问「产出为零是设计态还是死」。
