# 指纹闸载浮点噪声（self_aware 实证）

**坑形**：`gaugeDue` 同纹抑制闸的指纹输入里混进**每拍必漂的浮点串**——
self_aware 初版把展示段 `move`/`stuck`（载年龄 `评:动(1m0s)`、
计数 `唤起无果1`）直接喂 fpHash。年龄每拍漂→指纹每拍异→
「6h 同纹续窗」永不命中→量表从设计拍的「结构变才报+6h 续窗」
退化成 ~60s 一行洪灌：append-only 账 68 行/75min，真结构变被淹没，
expect 监护件的断供判据也被高频产出遮蔽。

**判别**：量表发射拍距 << 设计窗=指纹漏噪声首嫌。两帧 note 逐段 diff，
肉眼段全同而 fp 异=fp 输入含展示面未见的浮点件（年龄/计数/时间戳）。

**修法**：展示串与指纹件**分离建册**——展示行保留年龄/计数给人读，
fpParts 只收结构集：器官态（名:态 无龄）、间歇件分面（名在动列∨息列）、
旗名（不带数）、办数。本坑实修=并行维护 mv/mvFp、flags/fpFlags 双册。

**推广**：凡「指纹去重/同纹抑制」件——**指纹输入白名单化**,
默认禁收任何展示串；展示与纹同源时必须先剥浮点（龄/数/戳）。
写新量表时自测=同输入跑两拍,fp 必须同。
