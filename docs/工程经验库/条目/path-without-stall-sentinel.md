# 径在无人盯=静默死径——凡新径必配滞留哨

**病灶族（三案同源 2026-11-10/11）**：

1. `条件请求` 事件型有写入径无渡出过滤——机器开口行靠蹭摘要
   露脸（修：urgent 道补过滤）；
2. `求助值守` 同理补齐（与①同修）；
3. 「转要码修」处置转换——工单写在处置行 note 里,
   非一等票型,转了没人开修会永远安静躺着,
   升件有陈化哨它无。修分两层：哨=`codework_stall`
   探针（双臂:工单真行过期∨旧形升件陈>24h未销）;
   本=`event='工单'` 一等票型——立票真行自载期限
   （期限=Nh 默认24h）,销=处置行「工单#id」——
   票即状态不靠散文载（2026-11-11 业主令：
   不养散文判定,直接上一等票型）。

**判据**：新立一条径（事件型/转换型/队列型/通知型）时必问
「物在里面停住,谁知道?」——答不上=此径静默死径预备。
配对哨型：

- 队列型→陈化哨（未决>Nh 升件,沿 codework_stall 判据）;
- 事件型→渡出过滤+活性探针（存在未渡行而水位不走=径死）;
- 转换型→「转后无落点」探针（源件销了而目标件从未生成）。

**判词**：「名义上是实际上不是」的头号变体——径的配置存在
让人以为径活着,只有滞留哨能区分「安静=没货」与「安静=死了」。
