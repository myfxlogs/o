# 豁免册∩能力册须=∅——陈废豁免静默再放行（O-41387）

**坑形**：`drillUnsupported` 白名单语义=「显式裁定无可演习腿形」。
O-41370 落 `ShapeGridBot`（grid_spot）、O-41368 落 `ShapeCFDSingleLeg`
（mt5_dir_mom）后，两条豁免**仍在册**——能力注册表（`excell.LegShapeOf`）
前进了，豁免册没跟上。后果不是即时错（`TestExecfamLegShapeAlign` 双向
容忍：有形 OR 在豁免都过），而是**闸弱化**：日后若有人撤映射，残留
豁免会把「无形族」静默再放行——对拍闸的牙被自己的豁免磨掉。

**根修三件套**（同型豁免册通用）：

1. **撤陈废条目+史注**：删条目不删裁定史——原工单号留注释行
   （「#25840 裁定史——O-41370 腿形落成后豁免废 O-41387 撤出」），
   禁整行无痕删（裁定链可溯）。
2. **回归哨断言**：`册内任一条目 ∩ LegShapeOf ≠ ∅ → RED`——机器对拍
   取代人工巡检，新增腿形忘清豁免自红。
3. **三步实证**：先落断言亲见 RED 报出 stale 名单→修→自绿——
   「断言先见红」是验收钉，防修的时候顺手改断言迁就现状。

**判别式**：凡「白名单/豁免册」与「能力/注册表」两册并存的面，
交集非空即病灶——豁免的有效性是相对能力面的，能力前进豁免必须
同 commit 或紧随 commit 撤出。
