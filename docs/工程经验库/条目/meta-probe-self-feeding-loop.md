# meta-probe-self-feeding-loop —— 探针去探探针/工单/会话自身=自喂环，注意力被自家免疫系统占满

## 坑
把「机器自己的工单、会话、探针有没有按时动」做成升件探针（票滞留、销后复燃、热域、帧契缺口、码工滞留、器官催办、自审日拍……），每条升件都要一个会话来「处置」；处置=销案，条件不变=下拍复火，于是出现「探针→会话→处置行→新探针」的正反馈。它们单看都有道理（每个都对应过一次真实漏项），合起来把认知环变成了行政环。

## 实证（2026-11-16 外席普查，7d 窗）
- 升件约 670 条：机器看自己约 366（55%）、同一经营状况反复报约 172（26%）、命脉约 112（17%）。
- 销后 24h 同 scope 复火：stuck_esc 75/77、frame_use_gap 20/23——处置行多为「同 #N 判词」。
- 唤知机唤起 453 次，326 次触发词只有 ticket:N；同期真策略零成交。
- 工单板 37 张未结里 14 张是在修这些探针自己。

## 反证条件
- 升件探针只探**钱径、数据面、部署与认知环死活**；机器自身的流程健康（票龄、复火率、帧使用、未并支、新面）= KPI 量表或每日一行，不升件、不唤会话。
- 持续性状况是**状态**不是事件：变了才更新一行，不许「销了重火」。
- 新增探针前先答：它响了之后，除了写一句判词，会话能做的**下一步动作**是什么？答不出=不建。
- 施工有自己的拉取定时器后，不再需要「推」类催办探针。

## 机械化
- 减法 C 批（业主令 #20930）：上述探针撤编，票板/未并支/新面并为 `量表/housekeeping_daily` 每日一行；复火率等留在 `量表/seat_kpi`。
