# 宣称已修/已愈可被状态证伪——销了又火是机械复核臂

**病灶族**：处置会话写「已修部署」/「窗口内已愈」销案后,同 scope
升件又火——说明修复没落/界修错/愈是假愈,而机器自己不知道
（每场会话冷启动,对「我上次判得对不对」零记忆）。判词质量的
盲区不在「它判错」,在「判错了没有任何东西会响」。

**分界面**（2026-11-10 业主令,复审机械臂判据）：

- **状态可证伪宣称**（已修/修/部署/落成/修复/已愈/自愈/恢复/复绿）
  → `stuckEscCheck` 探针戳穿：处置行载修愈类词∧同 scope 复燃
  =升件。这类宣称说「条件没了」,条件还在=宣称死。
- **判词宣称**（误发/同判词销/定性销）→ 不在本探针域：条件存续
  复火是设计内正常流转（探针自复验）,不能拿「又火了」当证据;
  归审计抽查面回放当时状态。
- **销案载证**（runbook 值守令）：销件 note 须载可核证据——
  已修→commit/sha;已愈→复查实数。「无异常/应该没事」不是证据。

**配套**：`event='求助值守'` 事件型——技术阻塞（非业主域）写账
入 urgent 道,业主转值守。条件请求=要业主做事,求助=要技术支援,
分界在对象不在紧急度。

**判词**：复审不审「它说得对不对」,审「它宣称的事实」。嘴会糊,
状态不会。

**上岗首夜实案（2026-11-10，词表钉死）**：初版词表含裸
「修/部署/修复」——处置行写「探针修要码修在案」（待办语
非宣称）被误中,stuck_esc 报→会话销案→又报,一夜滚出
**13 代自指链**;处置席先值守一晚发现探针有病并立码修件。
修=词表钉完成态前缀：已修|已部署|已落成|已修复|已愈|自愈|
已恢复|复绿|上岸——「要码修/待修/需修/转单」不再误中;
runbook 词表对齐（判词用字自择,探针只认完成态）。
教训：文本匹配做状态判定,词表必须区分「宣称完成」与
「待办提及」——裸动词永远两头都中。
