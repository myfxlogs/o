# 「活着」的三个假面（同族三连实证）

**坑形**：活性/产出探针量的不是「语义产出」而是「写入触碰」或「拍返回」——
三层假面各遮一种死：

1. **写触碰掩盖语义死**（`ProbeKlineStale` 面②）：`max(recv_ts) WHERE
   confirm` 量收帧时刻——upsert 每拍覆写 recv_ts，收线确认停摆期
   形成中帧仍把 recv_ts 刷鲜。实证：confirm 棒 max ts 停 41.5h，
   recv_ts 却 1.5min 前刚被写——闸恒鲜，病灶隐身。
   **修**：语义列换 bar 时刻+周期换算（`max(ts)+24h`=收线时刻），
   阈按「末次应产出到现在」算不按「最后一次写」算。
2. **拍返回≠产出**（`armwatch.OK()`）：8 臂 scan 尾无条件 OK——
   「函数返回 nil」被记为「产出」。mt5_dir_mom 宇宙 367 inst 全
   陈棒→零判词卡→照常 OK→2×beat 告警永不触发，史零产出。
   **修**：OK 只在实质产出落位（判词卡/落账行>0）；宇宙空/队列空
   走 `Quiet()` 合理零产出不误报；宇宙在零卡=病灶窗让位告警。
3. **器官死活无账**（arch_daily.sh）：cron 重定向到不可写径死
   26 天，备份/快照/清理全停而无人看。**修**：`ops.cron_manifest`
   名单驱动产出账——文件 glob mtime / systemd LastTriggerUSec
   双定位形，超阈升件，名单空=不探防误报。

**判别**：「探针绿」不等于「面活」——先问探针量的是什么列/什么
返回值，它量的是不是业务语义的产出时刻。凡 upsert 覆写型表，
recv/write_ts 类列天生量「写活性」非「语义活性」，语义面必须
回到业务键（bar ts/订单状态迁移/产出文件 mtime）。

**修法**：语义产出面三选一锚——①业务对象自身时刻（bar ts+周期）；
②状态迁移计数（confirm 翻转/eval 行新增）；③产出实体 mtime。
写触碰列只配当「臂还活着」的旁证，永不配当「面在产出」的判据。

**推广**：探针验收反问句——「把产出停了、把写入继续，探针报警吗？」
答不出=量错面。O-38640 桩测即按此出题（写触碰掩盖案/陈棒零卡案/
产出陈案三断言全钉死）。
