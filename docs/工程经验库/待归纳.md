## sg-slow-module-download-image-ship（待归纳）

- 现象：SG（192.229.85.35）compose build 拉 golang module 50min+ 未完（宿主网络到 proxy 慢）。
- 范式：本机 docker build → `docker save img | gzip -1 | ssh SG "gunzip|docker load"` → SG compose up（不重 build）；source 仍走 deploy_sync 保持跟踪面一致。
- 判据：SG 构建慢于 ~15min 默认换镜像直达径；go.mod 变（新依赖）时尤其。观察复用一两次后升条目。

## migration-number-collision（待归纳——已两犯）

- 现象：施工分支基于旧 master 立号，期间他单合入同号迁移——T-0040 立 0025 撞 T-0041（merge 6cac7f8 改号 0026）；T-0044 又撞 0026 改 0027。两犯=系统性。
- 范式：立迁移号前 `git fetch origin && ls origin/master:migrations | tail` 现查最新号；施工中 rebase 时必核 migrate_table.go 尾行与 migrations/ 目录一致性（重复 version 号静默双注册）。
- 判据：登记表 version 唯一性无 DB 级约束——靠人肉；建议后续单加机检（duplicate version in migrate_table）。

## bulk-edit-silent-noop（待归纳）

- 现象：python str.replace 批量改码，目标文本与实际不符时**零报错静默不改**——T-0064 sizing.go quote_ccy 编辑两度落空（第一次 T-0062 反推块失配、commit stat 缺文件才暴露）。
- 范式：批量改码后必核 `git diff --stat` 文件清单与意图面一致；replace 计数断言（`assert old in s`）；或直接用 Edit 工具带唯一锚。
- 判据：commit stat 缺预期文件=编辑未生效体征。
