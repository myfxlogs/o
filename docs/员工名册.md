# O 员工名册（编制册）

> `[角色:决策]` 立于 2026-10-23（D-0004）。业主令 2026-10-23：「给他们取 1 个名字，约定他们的职责，以此来判断工作是否合格」。

## 0. 总规

1. **岗位制**：名字挂**职能岗**不挂协程人头——一个 daemon 岗位=一个员工名；同岗多实例=该名+N 号。禁虚构岗位（无虚席，D-0003 锁①）。
2. **一职一卡**：每个员工一张职责卡——职责、产出、频度、**合格判据**、越权禁线。职责卡即验收判据载体。
3. **合格判据全机读**：出勤（心跳/班点在窗）· 履职（产出物在窗）· 不越权（写权不越域、数据面纪律适用者必守）。**纸面 KPI 禁入**——判据必须能由系统自算（D-033）。
4. **名册 vs 编制**：本册=编制表（设计档）；运行时 `fin_employee_registry`=在花名册（`Register` 入册、`Beat` 只 UPDATE 不 INSERT）。**编制有而运行无=缺岗；运行有而编制无=私岗**——两皆须报。
5. 补编随施工推进；新员工上岗=先补卡再注册。

## 1. 职责卡模板

```
| 名 | 二字职能名（见卡知职） |
| 岗 | daemon/脚本/工具标识（仓内坐标） |
| 域 | 数据/研究/投资/风控/交易/账本/平台（编制挂靠=写权域） |
| 形态 | 常驻流 / cron班点 / 事件驱动 / 工具随调 |
| 职责 | 一句话：它保住什么不发生什么 |
| 产出 | 必须落地的物（表行/报告/文件/告警） |
| 合格判据 | 机读判据：出勤窗 + 产出窗 + 越权线 |
```

## 3. 考核口径

- **出勤**：常驻=心跳 Beat 在窗；cron 班点=计划时刻±容忍窗内有产出；事件驱动=该发时必发（以产出证）。
- **履职**：产出物在窗且过其域的数据面纪律（流正路/新鲜度/单源真）。
- **越权**：写权越域、runtime 病灶入请求箱、考勤式产出——任一=不合格。
- 不合格=先告警（自警/分诊径），重复不合格=立票；**员工不替系统背锅，也不给系统遮锅**——判据读的是产出不是意图。
