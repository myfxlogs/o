## 二、真实防御链（会话层）

防闸之外是防痕：ops_event 追加制 + prev_hash 链（ops_event_chain_trg）→ 伪造不可防但永久可溯+篡改可证；自报惯例（代录行须申报「外席代录」）；唤起行由真实调度件写=相对硬的身份基片。

**定性**：席位闸防过失（写错事件类型被拦），不防蓄意（自报双席行）。符合威胁模型——会话皆业主授权件，防的是手滑不是内鬼。canon 条目 `seat-identity-selfdeclared` 已落档定口径。

## 四、工程径（同日续审）

| 闸 | 裁决 | 实证 |
|---|---|---|
| 推形闸（origin唯一/master只许部署树/禁force删映射） | 机械——钩运行时 | `scripts/hooks/pre-push` 实拦；`core.hooksPath=scripts/hooks` 版本化钩 |

| land_queue合闸（戳鲜/复审/migdep/merge-tree) | 机械（自报语义内） | 复审独立性=会话层已判约定，此处不重复 |
| GitHub build-test必查 | **检出非预防** | `pr_required=False/restrictions=None/strict=False`——直推master不受闸，CI post-push才跑；戳注释「服务端兜真伪照拒」表述夸大，实为事后标红 |

**工程径判：防过失机械+防蓄意约定+检出机械。** 会话持/opt/o+push权=可伪造戳+改前缀+直推master，15min内deploy_watch自动部署；事后标红=GitHub CI master红+部署账+git史+产线探针四重检出。威胁模型自洽（授权会话+可追溯）。

## 六、总结论（三层合判）

**O的免疫形态=「防过失机械+防蓄意约定+篡改检出机械」——三层一致。** 不是缺陷而是威胁模型的如实映射：会话皆业主授权件，防手滑+保证可追溯即足。升机械预防的已知径：最小权限DB角色（o→app_rw无UPDATE/DELETE）/GitHub push restrictions（须先改land_queue为PR流，大改）/分席凭据。当前均不值，如实定档。
