# 提案：票号原子发号——DB 序列消撞号类（外派施工件）

- 状态：**已批**（业主令 2026-11-08 直裁绕 CTO 串行——「立，同样给
  外派」）；外派施工→COS 复审→COS 部署（GW-001 同权例）
- 域：工程基建；RSI 方向锚——拆 CTO 串行堵点的先决件之一
  （发号原子化后「裁定分道」才真可行）

## 一、病灶

实证 2026-11-08 单日三连撞：T-0475→T-0477→T-0479 重编、T-0483
done/ 撞号被 pre-commit 闸拒收。现行 `scripts/next_ticket.sh` 扫
远端最大号+1——两席并发取号必撞；merge 期撞号=重编/闸拒/返工。
串行裁曾是防撞的代价——原子发号把这个理由拆掉。

## 二、建造面

1. **序列**：migration `fin_0151_ticket_seq.sql`——
   `CREATE SEQUENCE fin_ticket_seq` 种子=现仓最大票号+1
   （含 tasks/ 与 done/ 两面）；
2. **消费径**：`scripts/next_ticket.sh` 优先 `SELECT nextval(
   'fin_ticket_seq')`；DSN 缺席/查询败→回退现行扫号径
   （fail-open——与今天行为一致，不差）。
3. **对账桩**：新增断言入 `check_ticket_numbers.sh` 或同级——
   `last_value ≥ max(现存票号)`（序回退=红，防分支带旧序列
   文件造成号码回跳）；漂移类可归段 F 探针后续对账。
4. **半成品窗**：分支上由扫号径创建的票（迁移未应用环境）
   仍可能撞序列票——merge 期既有「重编让号」流程照接，
   不新增行为只兜底；票据面上 ticket_seq 与扫号并存期
   需写明（提示词评估项）。

## 三、判据

- 并发两席取号→异号（桩测双线程 nextval 实证）；
- DSN 缺席→回退扫号径行为不变；
- 人造序列落后（setval 调低）→对账桩红；
- 全谱零新增 FAIL/SKIP。
