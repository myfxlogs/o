# T-0173 前端最优解设计修订——Watch v2 数据内推 + React 18 原生订阅 + 视觉层级

> 修订 T-0173 前端收尾移交书——业主令：要求最优解。以下为相对前版的架构升级+视觉层级重排。

## 一、数据层升级——Watch v2 数据内推（消除重拉往返）

### 现状（两跳）
```
后端 PG NOTIFY → Watch 流推 {kind:"ev_cashflow"} → 前端收通知 → 再发 unary 拉数据 → 渲染
```

### 最优（一跳）
```
后端 PG NOTIFY → Watch 流推 {kind, payload:数据} → 前端直接渲染
```

### 改动
1. **proto**：`WatchEvent` 加 `google.protobuf.Struct data = 3;`（载荷字段）
2. **后端**：`service.go Watch` 循环——NOTIFY 到达时查对应表最新行，序列化进 `data` 字段推入流（按 kind 路由到对应表查询：ev_cashflow→ListHedgeFlow 最新 10 行、ev_position→ListClosedPositions 最新 5 行、ev_hostmetrics→GetHostMetrics 全量）
3. **前端**：`stream.ts` 收帧时解析 `data` → 写入 `useSyncExternalStore` 全局 store → 组件自动重渲（消除逐卡 refetch）

### 收益
- 每次更新省一趟 unary 往返（~100-200ms）
- 前端状态统一管理（不再逐卡各自 fetch+state）
- `useSnap` 自制钩子退役 → `useSyncExternalStore`（React 18 原生，零依赖）

## 二、状态管理升级——useSyncExternalStore 替代 useSnap

- `store.ts`：全局 `createStore` + `subscribe` + `getSnapshot`（按卡分片订阅）
- 每卡只订阅自己关心的切片（Watch 数据到达 → 精确通知对应切片 → 只重渲该卡）
- 替代 `useSnap` 的 `useEffect+useState` 样板（减少 re-render 面积）

## 三、视觉层级重排——TRX 页核心数字优先

### 现状
四瓦片等宽等高，核心数字（年化/待领取/强平距离）与次要标签（样本天数/口径注释/刷新时间）视觉权重相同。

- **次级瓦片**：雷达/对冲双列——标准 14px
- **明细层**：流水/历史订单——全宽表格，13px

## 四、玻璃态加强——噪点纹理+微交互

- backdrop-filter: blur(20px) saturate(180%)（现有）
- 加 `background-image: url("data:image/svg+xml,...noise")` 噪点纹理层（opacity 3%）
- 卡 hover: translateY(-3px) + border 亮起 + 内发光加强
- 玻璃面上下边缘 1px 渐变高光线（模拟真实玻璃折射边缘）
