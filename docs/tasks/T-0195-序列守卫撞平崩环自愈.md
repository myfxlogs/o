## 病灶实证（T-0193 部署期真实发生）

`internal/projector/reconcile.go` 起服守卫：`md fin_*_id_seq next <= SG max(id)`
→ fail-closed 不起。T-0193 部署时实测：`fin_proposal_id_seq` next=300016 恰平
SG max=300016 → **每次重启掷骰崩环**，人工 setval 抬位才起服。

语义张力：md 是提案/eval id 正本（dev 唯一发号），SG 侧 max 由镜像行+遗产行构成。
SG max 追平 md next 是可达稳态（镜像落后/遗产大 id 段），守卫把「重启」变成
了外部干预依赖——可用性病灶，非安全语义（守卫本身要留）。
