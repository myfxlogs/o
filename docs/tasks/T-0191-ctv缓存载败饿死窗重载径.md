> 域：`internal/data/okxws`（collector.go ctv 预载+handle.go books5 闸）

## 病灶实证（决策席取证在案）

```
depth5_no_ctval = 13,479（帧级拒因计数器）
ctvFeed 载入点：collector.go:183-189——仅连接建立时调一次，
  载败→rej.Inc 一次→c.ctvCache 恒 nil/空

    8min 重连窗≈数千拒——13479 计数构成实证）
  →下轮重连碰运气才解——「载一次败饿死一窗」结构病
```

当前态：ctvCache 已载（depth5 11 行 0.7s 鲜在流）——**窗口型病灶
非当前死**，但下轮 instruments 读败即复发。

## 修法钦定（二选一，施工判）

**甲案（首选——自愈节流）**：books5 帧到且 ctvCache 空/无此 inst
且距上次重载 >60s→后台重载一次（节流钉死防帧频打 venue）。
载成自通，不绑重连周期。

**乙案**：ctvFeed 独立定时重载（5~10min 一拍——ctVal 本身低频变，
与连接生命周期解耦）。

钦定豁免语义：载败仍 `depth5_no_ctval` 计拒（真源钉不藏），
但**载成即通**不等重连。

## 验收锚

1. ctvFeed 载败场景下 books5 不再整窗饿死（桩或断网重载实证）；
2. 重载节流 ≤1 次/60s（venue 侧调用频不炸）；
3. `depth5_no_ctval` 拒因增速在载败窗后自动归零（不再持续到
   下轮重连）；
4. depth5 行持续流入不回归。
