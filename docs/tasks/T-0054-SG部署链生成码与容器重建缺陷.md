## 背景

T-0051 验收轮换实测暴露两缺陷叠加，后果=**SG 容器自 T-0048 轮换起一直跑 05:46Z 旧镜像**（回撤硬线/事件化等新码面未上车，本轮 09:27Z 已人工修正至 2bf0480f）：

1. **deploy_sync.sh 陈件 prune 误删生成码**：prune 差集按「git 跟踪 .go」算——`internal/gen/**`（gitignore 产物）不在跟踪清单 → SG 侧生成码每轮同步即被删；本地重喂前 build 必炸。
2. **Dockerfile.core 只重生成 core 模板**：`buf generate --template buf.gen.core.yaml` 单模板——mt5 面（buf.gen.mtapi.yaml）不在镜像内 regen 清单，宿主生成码缺席=编译必炸（T-0048 起新增面）。
3. **复合放大器**：compose build 失败被 `| tail` 管道吞退出码 → `up` 照跑 → 容器带旧镜像「Started」假象；且 `up -d` 未加 `--force-recreate` 时容器保留旧镜像运行（08:59Z 构建 6dac897 但容器仍 59ea0e1 实证）。

## 验收标准

- [ ] Dockerfile.core build 阶段补 `buf generate --template buf.gen.mtapi.yaml`（镜像内自洽双模板，宿主 gen 面零依赖）
- [ ] deploy_sync.sh prune 排除 `internal/gen/**`（或 build 前 SG 侧自动 buf 重生成二选一，结果段记所选）
- [ ] SG 轮换 SOP 修正进 §11/collab：build 退出码显式断言（禁管道吞码）+ `up -d --force-recreate` + 容器 `.Image` 与新建镜像 ID 比对步骤
- [ ] SG 实跑一轮轮换：新镜像 CreatedAt 晚于 merge 提交、容器 running_img=新镜像、healthy
- [ ] 机检全绿；CI 绿

## 范围外

- 部署面以外的 gen 策略重议（如 gen 入库）；alpha-* 栈
