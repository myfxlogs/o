## 背景

M1 最后一环：复盘写回 G2，评估卡判据自我进化。采纳 DSHQ 五池远期验证模式——**决策后多时间窗复测+否决提案同样复测**（拒对/拒错=提案闸质量考据），判决书 verdict 分级不二元。

## 范围

1. **`fin_review` 表**：一仓一判决书——position_ref、verdict 闭集分级（strong/mild/marginal/falsified）、eval_card 预测值 vs 实际净额对比列、归因标签（fee_drift/funding_flip/slippage/model_err/luck）、复盘时间戳。`falsified` verdict=经济经验库回改点挂钩。
2. **判决书生成**：fin_position settled→自动复盘——预测 APR vs 实现净额偏差、归因初判（机读规则，禁 LLM 判钱）、verdict 定级。
3. **远期验证排期器**：`fin_forward_check`——决策点排期复测行（target_ts×对象×锚值）：已执行仓按结算点（8h/24h/72h）复测 funding 实现 vs 卡值；**否决提案同样排期**（若当时执行会怎样——拒对/拒错计入 fin_proposal 质量分）。到期行由复测循环填实际值+判对/错。
4. **写回环**：复盘结论→fin_opp_template 判据修正提案行（不自动改判据——提案态，投资决策面裁决后落 app_config）；falsified verdict→经济经验库待归纳行（坑=预测与现实的偏差模式）。
5. **员工**：`评史官` Register+BeatLoop(30s)，产出窗=fin_review/fin_forward_check 行。

## 验收标准

- [ ] fin_review verdict 四值闭集；settled 仓自动生成判决书（预测vs实现对比列+归因）；falsified→经验库待归纳行测试锚
- [ ] fin_forward_check 排期+到期填值+判对错——已执行仓与**否决提案**两路各一测试锚（否决提案复测=本票采纳 DSHQ 模式的核心锚）
- [ ] 复盘写回提案态行（非自动改判据）；import 闸零违；`评史官` 在岗；机检全绿；CI 绿

## 范围外

- 判据自动调优（提案→裁决是独立票）、退役流程细化（G11 后续）、MT5、LLM 复盘写作（复盘生成后 LLM 可写叙事，本票不做）
