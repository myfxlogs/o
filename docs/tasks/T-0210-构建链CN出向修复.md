# T-0210 构建链 CN 出向修复——mihomo 死后 docker build 断粮

## 态：待施工（钦定直派）
## 立项：决策席 @ 2026-10-28（T-0209 部署战实证）

## 病灶

mihomo 退役后 dev 裸出=CN 墙：`docker build` 内 `go install`
(buf/protoc-gen 四件）走 proxy.golang.org（Google 域不可达）；
改 GOPROXY=goproxy.cn/aliyun 后通用件可拉，但 buf 依赖里的
buf.build/pluginrpc.com 冷门模块**镜像回源僵死**（连接半死永不超时
——.zip.tmp 挂在 fd16 实证，0.3%CPU 等 28min）。
本机构建链自此断粮——deploy_image.sh 无法产出新镜像。

## 热补已行（今次部署径，非终态）

宿主 `~/go/bin` 二进制（buf1.74.0/protoc-gen-go1.36.12/
grpc1.6.1/connect2.0.1——钉版全中）COPY .buildtools/ 缝镜像
+gcompat 垫 musl（buf 为 glibc 动态链）——T-0209 即此径上岸。

## 钦定修法（二选一，施工证后决）

- 甲·工具件入仓：四件钉版二进制 vendored（~100MB，git-lfs 或
  定期刷新脚本）——构建零外网依赖，最稳但仓重。
- 乙·GOPROXY 链+重试：`GOPROXY=https://mirrors.aliyun.com/goproxy/,https://goproxy.cn`
  并 go install 外层 timeout+retry（僵死转败而非永等）——仓轻
  但镜像回源病靠重试概率穿。
- 附带必修：`web` 段 npm ci 走 registry.npmjs.org（CN 可通但慢）
  +alpine apk 源换 mirrors.aliyun.com/alpine（热补实证径）。

## 验收锚

- 裸机 `docker build -f Dockerfile.core`（无 GOPROXY 环境注入）
  一次过——重跑三次全绿。
- 钉版不动：buf1.74.0/插件版本与 ci.yml/go.mod 同号断言。
