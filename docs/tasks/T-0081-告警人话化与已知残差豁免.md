# T-0081 告警人话化与已知残差豁免（业主令 2026-10-25——「我看不懂，不知道怎么处置，有必要发我吗」）

## 背景
ledger_diff_alert 实弹暴露三重病灶：
1. **黑话载荷**——「账实差超限——人工对拍」无差值、无原因、无处置径
2. **无处置性推送**——推给业主的事必须业主能处置（出资/凭据/权限）；对账差业主对拍不了
3. **已定性残差照样报**——$3.34 粉尘账外已定性（T-0080 在修），仍按未定性告警级每小时响

## 钦定规格

### ① 告警载荷人话模板（全部 kind 统一，不只本种）
```
[PHASE告警] <白话标题>
发生：<什么事>，差多少/多大
定性：<已定性=原因+在修票号 | 未定性=需排查>
要你做：<无需操作 或 具体动作>（业主只应条件请求——出资/凭据/权限三域外不出「要你做」）
```
禁内部黑话（ledger_diff/kind 名/表名直出）——kind 移进括号小号字尾注。

### ② 已知残差豁免表 `fin_known_residual`
- 列：venue, ccy, amount_usd, reason, ticket_ref, expires_at
- 对账逻辑：`差值 > 容差 + 该 venue/ccy 未过期豁免总额` 才告警——**豁免只压「已定性部分」，新发生的 unexplained 超额仍即报**（不可做成白名单静默一切）
- 豁免行必带 expires_at（如 7 天）+ticket_ref——超期自动复报，防豁免成永久盖布
- 本票落地时种入首行：okx/USDT ≈$3.4（粉尘账外，T-0080）

### ③ 处置性闸
- 告警出口前判「业主可处置？」——出出资/凭据/权限三域的 kind 降级为 `[经营事件]` 级（仍推但标事件非告警）或页面级；分档表写在票面实现节，施工按「向业主推=行动呼唤否则降级」原则枚举现有一切 kind

## 验收
- 种入豁免行后 ledger_diff_alert 停推（残差 $3.34 < 豁免额）
- 人为制造一个新差（如测试改 venue 读值）→ 告警按新模板出「差 $X｜未定性｜要你做：无需操作/排查中」
- 退避阶梯保留（未定性持续差仍 5→60min 递进）

### 返修回填（2026-10-25——退避指纹根修 @cf65312）

- **指纹 kind|payload→kind|title**：payload 变额每抖重置阶梯=持续差退避失效病灶——title（HumanText 白话标题稳定）定指纹，同病同阶退避阶梯守。
- **测试锚**：fnvOf 期望值同步 kind|title 口径——BackoffLadder 全档绿。
