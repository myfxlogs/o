## 病灶

行鲜度哨兵只管「数据来没来」，管不到「判词说什么」——
evalCarry 错表名/basis 缺 apr/product_rows_missing 各以
unevaluable 判词挂账数周无人见，因无任何面把 verdict 分布/
队列转化率当人看的信号。fail-closed 语义正确≠停摆可观测。

## 钦定修法（数据面已全在，只欠读面）

健康板/系统页加「评估与队列」域，四行起：

1. `fin_opp_eval` verdict 分布（proposed/rejected/unevaluable 三色
   计，unevaluable 占比>阈告警）+ top 3 reason 值（按 evidence->>reason
   聚合——判词分布漂移一眼见）。
2. `fin_proposal` 状态漏斗（proposed→armed→executed 计数+最大龄期
   ——armed 积压龄超阈告警）。
3. `fin_opp_hypothesis` proposed 卡数+最老龄期（审批队列积压可见）。
4. `fin_opp_template` candidate/enabled 分色（新族未启=候选态灰显）。

谓词全部现成可查 SG o-postgres；新组件 host 标 `sg`、cat `ops`。
