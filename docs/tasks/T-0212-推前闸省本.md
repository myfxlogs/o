# T-0212 推前闸省本——tip 戳+Go 测试缓存放行

> 状态：已立单待施工 | 优先级：P2（日常摩擦级）
> 起因（业主令 2026-10-28)：现闸「每次改动都全量 uncached 重跑」=
> 每次 25-40min，代价太高；「如果只跑 1 次还好」。

## 病灶

`scripts/check_all.sh` 里 `go test ./... -count=1 -timeout=1800s`——
`-count=1` 禁 Go 测试缓存，全仓 ~70 包每次全跑（guard/ledger 等重件
包分钟级）。绿戳按 commit SHA 记——docs-only commit 也须全谱重跑。

## 钦定修法

1. **戳域收窄到 push tip**（已部分如是）：pre-push 只要求被推送 ref 的
   tip SHA 有戳；一次多 commit 推送不重付戳（语义已是，核实钉死文档）。
2. **去 `-count=1`**：让 `go test` 吃 Go 构建缓存——同 tree 复测近零
   成本；docs-only commit 因测试输入无变≈秒级出戳。
   风险评估：缓存致「改了但没重测」的窗=Go 按文件/依赖指纹判缓存，
   非按 git 状态——语义上比 -count=1 弱的是「环境/外部依赖变动」不触发
   重测（如 PG schema/venue 行为变）。钦定：**去 -count=1 放行缓存**，
   外部依赖型测试若存在应另标 build tag 或显式 -run 清单保 -count=1
   （施工先普查哪些 test 依赖真实 PG/网络）。
3. 保留全部静检件不动：import/gofmt/env-read/reject-keys/migration
   七断言——这些本就近零成本，不在省本面。

## 验收锚

- 同 tree 连跑两次 check_all：第二次 ≤2min（缓存实证）
- docs-only commit 出戳≤2min
- 推送仅验 tip 戳（两 commit 推送不重跑）
- CI 侧语义不变（服务端 check 仍全谱）

## 施工回填（@分支 t/0211-ueval-natkey，T-0211 同支捎带）

1. **tip 戳域——核实已是钦定形**：pre-push `while read local_ref local_sha`
   逐 ref 验 `.git/check-green-<local_sha>`——被推送 tip SHA 持戳即放行，
   一次多 commit 推送天然不重付戳（中间 commit 无戳不拦）。无需改码。
2. **去 `-count=1`**：check_all.sh `go test ./... -timeout=1800s`——

   输入无变≈秒级。外部依赖型（真实 PG 实例测试）陈判窗钦定放行，
   CI `go test -count=1` 服务端全谱兜真伪未动。
3. 静检件（import/gofmt/env/rejects/migrations 七断言）原位未动。
