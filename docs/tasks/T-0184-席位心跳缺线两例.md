# T-0184 席位心跳缺线两例——Register 有 BeatLoop 缺（活性台账假死）

## 态：可领

## 病灶（实拍）

fin_employee_registry 两席位心跳冻结但工作照跑：
- `信号蒸馏`（internal/research/sigdist/run.go）beat 停 2h 前——
  collector 重启时点；md_signal 526 行 1s 鲜=臂活着心跳死
- `清道夫`（cmd/core/retention.go）同款——日拍清道照跑 beat 陈

根因钦定：两 Runner 均只 `roster.Register` 未 `go roster.BeatLoop`
（对照现役：risk/execution/okxws/trx.go 等 8 处全带
`go roster.BeatLoop(ctx,pool,seat,30s,errc)`——缺一行=活性台账假死，
业主看席位面板误判死岗）。

## 施工面

两处各补 `go roster.BeatLoop(...)`——池选 roste 径 target(pool)
（sigdist 用 r.pool、retention 用 pool——与 register 同参同池，
BeatLoop 内层自走 SetRegistryPool 重定向——照抄现役 8 处同款）。

普检件：全仓 grep `roster.Register` 对拍 `BeatLoop` 覆盖——注册无
beat 的席位若还有第三例同票根治（集使退役态除外）。

## 验收锚

1. 双席位 last_beat 转入 30s 级新鲜（SG 库实拍）。
2. 普检清单列出（Register 面全数有 BeatLoop 或无 beat 的如实注明）。
3. 无既有拍频/写径语义变更。
