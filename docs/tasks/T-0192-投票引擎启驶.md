### 返修① scheduler 12:00Z 静默定谳+修（最高优）
- **症状**：12:00Z 边界窗引擎零动作——无评估/无 claim/无报错（boot 补评估 11:38Z 已把 lastEval 顶到当时，此后自主拍未鸣）。
- **定谳路径**：读 `scheduler.Run`——判定是 ①自主 tick 丢失（移植丢件类）还是 ②boot catch-up 把 lastEval 置 now 后语义吞掉下一窗（补评估应只补「已过期未评」的窗，不得吞下一窗）。
- **修后验证**：下一 18:00Z 窗边界评估日志在案（evaluate/kick 任一形式）。

### 返修② 触发链饿死修
- **症状**：账户读失败（apilist 429→gRPC backup Unavailable 双败）→reward delta kick 断→引擎彻底哑（触发链单点）。
- **修法**：账户读失败时补退避重 kick（60s/300s/900s 三级退避直到读通——心跳语义，行内 sched-exempt-ok 律）；votes 读路加 429 单次退避重试（boot 风暴实证：多路并发 fetch 撞限流，稳态低频不撞）。
- **读路稳态**（实测维持）：主=apilist votes（无 key 200）+备=trongrid gRPC（Unavailable 病因随①一并查——容器内 gRPC Unavailable vs 宿主 200 的出网差异需定位）。

### 返修③ witness 读路 fallback 补线（与 votes 主备对称）
- **主**=apilist /api/witness（无 key 200×3 实测）；**备**=trongrid /wallet/listwitnesses（带 trx.trongrid_api_key 200 实测，key 已在 config）。
- **shape 差异处置**：trongrid 返回 hex 地址（41 前缀）无 annualizedRate 字段——①hex→base58 转换（gotron address 件）②年化沿用「最近一次 apilist 成功值缓存」（cache-last-good，首拍前无缓存=该组退避不评，不臆造年化）。
- **测试**：httptest 双源 fallback 单测（主败备顶/主复主归）随行。
