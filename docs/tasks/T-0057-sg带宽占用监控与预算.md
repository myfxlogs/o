## 背景

SG 宿主总带宽 ≈5M（业主口径——Mbps 级或流量包月口径待实测分型）。NOX 实证教训：WS 订阅面无节制把带宽吃满→**整机网络受限**（SSH 都断=失明失联级事故）。PHASE 现在在线流面：OKX 公开流（tickers/books5/funding-rate/mark-price，实测 tickers ~95帧/15s）+OKX 私有流 4 频道+MT5 双流——**当前实测占用未知，是盲区**。

## 目标

带宽占用可见+超限可预警+订阅面有预算闸——不是砍流，是先量化再裁。

## 验收标准

- **现状实测量化**（取证锚）：SG 上 nethogs/iftop 或 /proc/net/dev 差分采样，给出 phase-core 实时 RX 速率（KB/s）+ 分流道粗拆（OKX pub/priv vs MT5）——数字入票面结果段
- **帧级账**：采集侧补 bytes 计量（per-channel frame bytes 落计数器或轻采样——方案自定，禁高开销全量行记）
- **预算闸**：`net.budget_kbps` 配置键+超阈告警（80% 预警/95% 临界两档）——超阈只告警不自动砍（裁量归决策席，防误伤数据面）
- **订阅面瘦身建议书**：各频道字节占比表+「砍什么保什么」候选清单（如 books5→books1、symbol 子集化、mark-price 降频）——裁决归决策席，本票只产数据与选项
- **NOX 事故对照**：确认 PHASE 订阅集与 NOX 事故期订阅集的差集在案（防同款复犯）

## 阻塞处置

主机侧取证权限不足（nethogs 未装等）→ 用 /proc/net/dev 差分+容器 stats API 替代径，不挂起。
