# T-0193 投影臂 ts 表过拍节流——串行 worker 挤兑根修

> 立单：决策席 2026-10-27（depth5 SG 面 15s~2min 游走撞死阈取证）
> 域：`internal/projector`（ops.go projectTsTable 过拍径）
> 量级：微件

## 病灶实证（决策席取证在案）

```
SG md_ticks：自产 34 键 0.25s 鲜；投影件 475 键 >1min 陈——镜像追不平
SG md_signal.depth5：11 行龄 15s~2min 游走（阈值 warn30s/dead2min 撞死）

机制：dualwrite 全量旁写期 qTicksDual `WHERE ts>wm`——dev md_ticks
  ~1034 键高变（collector 批写 ~256 行/s 顶），每拍 SELECT ~500-2000 行
  → WAN(SSH隧道)批写 ~1-2s/拍；ev_ticks 醒 ~2-4/s——拍率需求>供给
  → wm 永久落后每拍更胖（死亡螺旋）；wake cap1 塌陷下 ev_signal 拍
  偶得隙→signal 面排队撞死。
  serve 模式仅减 ~60% 体量——同机制不除，T+48h 终切后仍有复发窗。
```

## 修法钦定

**ts 表族过拍最小间隔闸**：`projectTsTable` 入口加 per-channel
lastPass 记——`ev_ticks`/`ev_markidx`/`ev_funding` 过拍间隔 ≥3s
（可配置常数钉死即可），`ev_signal`/`ev_dcd` ≥1s。不足即 return nil
——每拍本就是 wm 追平式全量捞，塌陷醒零损（同 cap1 合流语义同族）。
**禁**改 wake/监听层（事件面无辜——病灶在执行端拍率）；禁丢行
（wm 追平语义天然幂等，无行可丢）。

验收锚：
1. SG 投影件 md_ticks 非活跃键龄 <30s 常态；
2. depth5 SG 面行龄 <30s 恒（不再游走撞 2min 死阈）；
3. basis_ann/funding_view 等 signal 面镜像滞 <30s；
4. 隧道载荷降（少拍即省）——前后各拍一次对照留票面。
