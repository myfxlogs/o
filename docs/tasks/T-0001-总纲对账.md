## 背景

`docs/总纲.md`（搬自 nox `AGENTS.md` @ b43c02d6）内含两套层：§1 方向锚（业主钦定，PHASE 全继承）与 §3–§8 流程机器（席位制、STATE 票、D# 链、机检门禁）。PHASE 现行协议（`AGENTS.md`+`docs/collab.md`）是简化双角色制。两套并存，须对账定档——哪些机器照搬、哪些裁并、哪些废弃，逐条出 D 档。

## 目标

产出一张对账表（追加进 `docs/decisions/` 新 D 档）：nox 总纲每条机制 → PHASE 处置（沿用/改造/废弃+理由）。完成后修订 `docs/总纲.md` 头注的效力分层段，使任一 Agent 进仓无歧义。

## 验收标准

- [ ] 对账表覆盖总纲 §3–§8 全部条目，逐条有处置与理由
- [ ] 席位制（实施/复审/分诊/决策）vs 双角色制（决策/施工）的映射有明确定论
- [ ] D# 链 vs `docs/decisions/D-NNNN` 编号关系有定论
- [ ] STATE 票制 vs `docs/tasks/` 任务单制有定论
- [ ] `docs/总纲.md` 头注更新至与结论一致
- [ ] 产出对应 D 档（决策档案），业主批准处留痕

## 范围外

- 不动 §1 方向锚文字（业主令层级）
- 工程纪律/架构约束已定档（`docs/工程纪律.md`、`docs/架构约束.md`），不在对账范围
- 不实施任何机器搬迁本身（STATE/机检/门禁落位另立单）
