## 背景

当前 `dev_run.sh` 每次都在共享 scratch 目录启动全新 `devin -p` 会话。模型限流后，虽保留 worktree，补拉仍新开会话、重建上下文；并行闸固定为 2，在免费模型额度下容易同时消耗同一模型限额。限流退出也没有统一冷却闸，可能让后续票继续撞限额。

## 目标

- 每票拥有独立、稳定的 Devin CLI 会话目录；同票补拉时优先续接该票最近会话，不把不同票的上下文混用。
- 额度紧张时仍允许多票入队，但默认只跑一个施工模型会话；并行上限可配置且硬封顶 2。
- Devin 返回限流提示后记录全局冷却时间；冷却期内所有派发入口都拒绝新模型调用，决策席漏拉拍在冷却到期后续跑限流票。
- 不自动重试未知失败，不触碰现有 worktree/未提交代码。

## 实现约束

1. `devin list --format json` 只用于当前票独立会话目录的本地会话发现；发现已有会话时用 `devin --continue -p`，无会话才新建。列表读取败必须 fail-closed，不得悄悄新开会话。
2. 用单一 `dispatch_worker.sh` 作为派发入口；`dm_tick.sh` 漏拉补派和决策席常径派单共用。并发默认 1，`O_WORKER_PARALLEL_LIMIT` 只接受 1 或 2。
3. 限流冷却状态放在用户私有运行态目录（权限 700/600），不把 prompt、工具输出或 DSN 落入状态文件。CLI 诊断日志临时文件须 600 权限并在退出时清理。
4. 限流挂起必须有可机读标记；仅该标记允许冷却到期后自动续跑。其他挂起不自动重试。
5. 不运行 Devin 模型、不部署、不 push；只做本地实现与离线测试。

## 验收标准

- [ ] 同票首次启动新会话；同票重启会发现并续接；不同票会话目录相互隔离；会话列表读取败时不启动新模型会话。
- [ ] 并发默认 1，配置 2 时最多 2；同票活跃 unit 幂等不重复拉；超水位只留队列，不启动 Devin。
- [ ] 限流提示解析为冷却截止时间；冷却期内直接派单及漏拉补派均不启动模型；到期仅重拉带机读限流标记的票。
- [ ] 非限流挂起、一般错误不会被自动重试。
- [ ] `bash -n`、新增 shell 桩测通过；`check_all.sh` 按仓库门禁运行。

## 范围外

- 不改 Devin 账号/套餐，不触发额外模型请求，不改变票的优先级或审批权限。
- 不把所有任务合并进一个常驻对话；每票仍隔离为独立可恢复会话。
- 不部署或验证生产资金路径。
