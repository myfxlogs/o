# T-0369 容错必报契约——静默失败根修

- 状态：已批（COS 转录业主问案 2026-11-05——「其他的断点
  如何去发现」讨论裁定：病根=容错契约允许静默，最优解=
  源面自报契约非下游扫描）
- 领取：（待派）
- 级别：P1 机制补格——静默失败类断点发现机制

## 事实（实查在案）

- 标本：ops_ticket_usage 写径 `|| true` 容错位全败数月无
  人知——败讯只打 stderr（dm_tick `continuing` 容错滑过），
  唯一发现径=人肉读日志；
- 病灶定性：容错契约允许「静默败」——`|| true`/`|| :`/
  `2>/dev/null`/`continuing` 类容错位的失败面只有 stderr
  一个出口，无台账无计数无消费席；
- 与既有律互补：「死人闸」管信号**缺席**（对拍），本票
  管信号**失败**（自报）——正反两面合一律；
- 下游扫描（stderr 聚类/期望账对拍）降为兜底——不发明
  新扫描窗作主机制。

## 任务

1. **立法**：`docs/工程纪律.md` 增容错必报条——容错位
   失败**必须自报**（ops_event `写败` 行或直接 `升件`），
   禁只打 stderr；自报率受限（同窗去重防事件暴）；
2. **清单**：全仓扫静默容错位（`|| true`/`|| :`/
   `2>/dev/null`/空 catch/continuing 类），出嫌疑清单
   `docs/容错位清单.md`——每位标「败了谁知道」，答不上
   者入册待补报件；
3. **首用**：dm_tick usage 调用面败径改升件行（依赖
   T-0368 落账后在其新 stdin 径上改——同文件错峰，
   收口支基于其 merge）；
4. **机检候选**（供裁）：check_all 加 lint 档——新增
   `|| true`/`|| :` 无报件注释锚（`# tolerate: <原因>`）
   即违例——旧件豁免走清单对账。

## 验收锚

1. 工程纪律条目在册（容错必报+自报率限）；
2. 容错位清单落 docs（嫌疑≥N 位各标知情径）；
3. dm_tick usage 败径升件实证（注入败→升件行落账）；
4. lint 候选若采纳：违例注入实证+旧件清单豁免对账；
5. check_all 绿戳对口提交 SHA。

## 红线

- 不改容错语义本身——败了仍容错，只加自报；
- 自报走既有 ops_event/升件白名单径，禁新通知栈；
- T-0368 域零动（同文件错峰，收口基于其 merge 后）；
- stderr 聚类/期望账扫描**不做**（兜底降级件另裁）。
