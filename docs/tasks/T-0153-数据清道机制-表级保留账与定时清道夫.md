# T-0153 数据清道机制——表级保留账+定时清道夫+热表 vacuum 治理

## 态：✅ 验收毕投产（决策席 2026-10-26——首扫拍 24h 后实证挂账）
## 域：数据面治理 / PG 体积
## 源出：业主问「数据一直增长，有没有自我清理机制？是不是无底洞」——
  决策席实测账（2026-10-26）：SG 库 1.18GB，主体非无底洞但缺
  统一清道机制（见下病灶账）。

## 实测账（2026-10-26 实拍）

### A 类·状态表 upsert 热拍（行数封顶，体积平台期——非无底洞）
| 表 | 体积 | 活行 | 病灶 |
|---|---|---|---|
| fin_opp_eval | 696MB 堆（25MB 索引） | ~9.7k | UNIQUE 键 upsert 热拍，每更新留死元组——autovacuum 4063 次在挡（dead~4k），堆为可复用自由空间膨胀不归还 OS |
| md_mark_index | 193MB | 2.7k | 同上（tick 级 upsert，avac 5243 次） |
| md_ticks | 58MB | 512 | 同上 |

判：行数=键域封顶不无限长；堆体积=churn 工作集平台期。**一次性可回收但会再涨到平台期**——VACUUM FULL（锁表）或 pg_repack 只能当一次性美容，非持续治理；正解=表级 autovacuum 参数调激进（vacuum_cost_delay/scale_factor 下调）+接受平台期。

### B 类·审计追加账（真线性增长——按设计不可删）
| 表 | 行/体积 | 判 |

### C 类·已有自清（worked）
- md_funding 超表 retention=30d、md_equity_curve=90d——policy 在跑（各 1 chunk=旧块已自动 drop）。
- docker json-file 日志 max 3×50MB/容器——轮转在档。

### D 类·漏面
- **无统一保留账**：逐表 keep-window 决策散落在票里，机器看不到全景。
- fin_forward_check 判定终局行无过期窗。
- SG 盘 76%（44/58G）——deploy_image 每次船运镜像堆积无清理。

## 施工
1. **保留账数据面化**：`fin_data_retention(table_name PK, class, keep_interval, last_swept_at, note)`——A/B/C 类全表逐行钦定（决策席本票附初值见下），清道夫照表执行=新表不入账即报缺（fail-closed 面）。
2. **清道夫拍**：o-core 定时臂（每日一拍，复用既有 tick/巡检骨架）——
   B 类：DELETE WHERE ts < now()-keep_interval（fin_forward_check judged=true 且对象终局可 30d；paper_fill 随策略退役 90d）；
   A 类：不删行（状态表），只做 autovacuum 参数表级调优（`ALTER TABLE … SET (autovacuum_vacuum_scale_factor=0.02, autovacuum_vacuum_cost_delay=2)`）；
   D 类：deploy_image.sh 船运后 `docker image prune -f --filter "until=72h"`（保留近 3 天回滚余量）。
3. **体积哨兵**：库体积>阈值（如 5GB）或单表月增>1GB 告警——先于盘满发现新无底洞。
4. 桩锚：retention 账行驱动清窗删除幂等；未入账表清扫臂拒动+报缺；哨兵越阈告警真发。

## 保留窗初值（钦定）
- fin_forward_check（judged 终局）：30d
- fin_paper_fill（所属策略退役）：90d
- fin_risk_decision/cashflow/venue_bill/transition/proposal/strategy：**永久**（账链）
- md_signal 族（状态表）：不删行
- fin_opp_eval：不删行（评估态表——历史评估价值在 evidence，键域封顶）

## 验收锚
- 清道夫生产首跑日志在案（各表删行数如实打账）。
- 全表 retention 账覆盖=100%（无表未入册）。
- fin_opp_eval 表级 avac 参数生效（pg_class.reloptions 见值）。
- 库体积哨兵注册在告警面。
