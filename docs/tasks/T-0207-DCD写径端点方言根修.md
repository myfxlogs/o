## 真规格（双库互证：rust-okx + okx-client 源档）

| 步 | 真径 | 我方现状（错） |
|---|---|---|
| quote | **POST** `/api/v5/finance/sfp/dcd/quote` 体 `{productId,notionalSz,notionalCcy}` | `dcd.go:59` GET `?productId=&sz=`——405；且参名错（`sz`→`notionalSz`、缺 `notionalCcy`） |
| trade | **POST** `/trade` 体 **`{quoteId}`**——报价绑单 | `dcd.go:67` 体 `{productId,sz,clOrdId}`——三键全错：真径只要 quoteId、**无 clOrdId 幂等键** |
| order-status | GET `/order-status?ordId=` | 方法对（同族 GET 读面实证过） |
| redeem-quote/redeem | POST `{ordId}` / `{ordId,quoteId}` | **未实现**——平仓提前赎回径缺口（到期自动结算可过渡，但须票面钉明） |

## 钦定修法

1. `DcdQuote` 改 POST 体三参（productId/notionalSz/notionalCcy——
   notionalCcy 大概率 USDT，以 products 响应 notionalCcy 字段回填，
   勿猜）。
2. quote 响应解析取 `quoteId`（响应字段名以实测为准——data[] 行内；
   桩按 rust 库 `DcdQuote` 响应型对）。
3. `dcdOpen` 改 quote→quoteId→trade 链：quote 拿到的 quoteId 直接喂
   trade——「陈旧提案不盲执」语义自然保（每开必新 quote）。
4. **幂等坑钉死**：trade 无 clOrdId——歧态势（超时/5xx 后成否未知）
   **禁补单**，先 `order-status?ordId`（若有 ordId）或 order-history
   按 productId+ts 反查真态，再定补否。fin_execution 先落 intent 行
   承幂等（已有径照旧）。
5. redeem 面本票只落「缺口声明」（到期自动结算兜底），提前赎回径
   另票评估——但代码里禁假装有平仓径。
6. 坑条目 `okx-dcd-endpoint-dialect` 同 commit 追补：quote=POST 体
   三参/trade=quoteId 单参/无 clOrdId 幂等坑——**坑处置必填**。
