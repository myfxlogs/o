## 设计验证会签（[角色:决策] 2026-10-24）

**裁定：照准+补正两点**——方向对（硬线机械化是 live_switch 物理前置）、序对（demo→paper→probe 验证梯与 D-0007 首仓序合辙）、纪律对（-3% 定值只认业主令、kill_switch 无自动复位）。两点补正随票生效，不另行立单：

1. **「净权益」数据源钉死含浮盈**。票面现写「数据源=账本日切/fin_cashflow 结算面」——cashflow 只是已实现净额，持仓浮盈不在内。钉：净权益=`fin_venue_account_snapshot.equity`（venue 自报权益含 uPnL，对账环同基准）或「账本净额+持仓按 mark-price 盯市」合成，二选一在结果段记明所选与理由。**不接受纯 cashflow 口径**——只认已实现=给「长持亏仓藏回撤」留门（经典藏亏手法）。
2. **窗口不足语义改判**。票面「窗口内数据不足=不判+计数」开保护洞——恰恰开业首月（最不成熟的期段）无保险。钉：史不足 30d 时按**交易起点至今峰值回撤**（high-water mark）判，史满窗口后切 30d 滚动窗——两段语义写入键注释与测试锚。

附带三项（不挡验收）：migration 空号实勘=0017 起（票面 0013 滞后）；paper-24h 可用既有 dev 运行实证折算，不必清零重启窗口；「停活期 Earn」措辞歧义按「资金泊 Earn、开仓走赎回径」解读（与 T-0019 面一致）。

## 段一验收打回（[角色:决策] claude-glm 2026-10-24 @cb342b8）

机检/测试面全数亲验过（净库全量 84/84、32 包零失败；静态闸 build/vet/gofmt/import 39 边/lines/mig-contract 全绿；会签两补正落位合规；config 热启链 0001 触发器+LISTEN 实勘通过）——**一处实质缺陷，打回返工**：

- **触线后重平循环不存在**：`ddScan` 在 kill 已落后 early-return，`forceCloseAll` 永不再执行；`tend` 的 maxAtt=0 使首败即「重试耗尽」告警。场景：触线全平时一次瞬时 venue 失败 → 该仓 close_failed（dd_30d）→ 此后 dd 监视静默、scanOnce 的 evaluate 无 dd_30d 触发面 → **敞口在最大回撤时刻无限期开放**。回填「全平由 tend 节拍收尾」与码行为不符（tend 无跨拍重入径）。
- **修复要求（单点）**：tripped 分支不纯 early-return——仍有在仓行时每拍继续强平（复用 forceCloseAll，扫 `closed_at IS NULL` 未平仓面），重试上限/节拍走热启键（弃 maxAtt=0 首败即弃语义）；全平后归静默（不重复落闸、`dd_hardline_tripped` 计数只加一次）。
- 补测试锚：首败→次拍自动重平→closed；重试上限耗尽→持续告警不静默。
- 其余面（采点/判撤两段语义/复位语义/迁移/回填质量）验收通过——修复合入即翻段一完成，续段二。
