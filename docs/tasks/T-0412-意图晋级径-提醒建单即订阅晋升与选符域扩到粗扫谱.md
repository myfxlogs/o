# T-0412 意图晋级径——提醒/自选建单即订阅晋升+选符域扩到粗扫谱

- 状态：已批（业主直裁 2026-11-06——「B呀」=选晋级方案非删僵尸）
- 领取：t/0412-intent-promote @ /opt/o-wt/t0412
- 优先级：P1——用户面真需求堵死（建得起提醒但永远不评估+想订的符选不到）
- 收口移交归：决策席

## 背景（实锤病灶）

实证 2026-11-06：业主 UI 建 `fin_price_alert #1 TRX-USDT-SWAP ≥0.35`
→TRX 不在订阅宇宙（md_ticks 最新行=10-26，十一天死符）→评估器零输入
=**合法建单产僵尸提醒，无任何面告知**（闸 T-0399 合入晚于建单成漏网）。

同根：报价自选/提醒建单的选符域=`md_ticks DISTINCT fresh`（活跃订阅集
38 符）——业主想订的符在选择器里**物理不存在**。T-0401 已交付晋级盒
`fin_sub_request(venue,inst_id,requester,state,reason)`+collector 拾取
径，但提名方只有评估臂——**用户意图这个最强信号没接**（用户亲手要
的符=比任何判偏更硬的订阅理由）。

## 钦定语义

```
选符域:  md_ticks fresh ∪ md_tick_scan DISTINCT inst_id(粗扫谱527+)
        ——有行情的+被目录扫到的都可选,不在两域=拒(防typo)
建单径:  自选/提醒建在非订阅符→同事务插
        fin_sub_request(venue,inst_id,requester='user_intent',
        state='pending')→collector拾取流式采→提醒变真
闸语义改: T-0399死符拒建→「不在catalog拒/在catalog未订阅=收+晋升」
僵尸修复: 存量#1 TRX行一次性写fin_sub_request复活(随本票迁移
         或建单重放,择其一,判词留痕)
```

## 范围

1. 选符域改：watchlist/alert 候选 SQL 改 md_ticks∪md_tick_scan 并集
   （quotes_watch_face.go 候选查询+提醒建单径同改）；
2. 建单同事务：非订阅符建单插 fin_sub_request（requester='user_intent'）
   ——沿用 0401 盒 schema 不改表；
3. T-0399 闸语义改判词：拒因从「死符」细化「不在目录=拒/可晋升=收」；
4. 存量修复：fin_price_alert #1 的 inst 写 sub_request 复活行；
5. 探针：晋升滞留（user_intent 请求超龄未采）入 0394 枚举面——
   用户提的请求死了必须能告警；
6. 前端：选择器对「未订阅」符给标（如 dim/角标「晋升中」）——
   用户该知道此符报价要几秒后才来，禁伪装有行情。

## 验收

- 红桩：建在catalog未订阅符的提醒→sub_request行落+collector拾取
  +该符md_ticks复活→提醒可评估（端到端真通电,不止建单行）；
- 存量#1 TRX复活实证（生产对拍行）；
- 选择器含TRX类未订阅符(带「晋升中」标)；
- 不在catalog的typo符仍拒（闸没放松到裸奔）；
- 绿戳对口+全链；探针新枚举有桩。
