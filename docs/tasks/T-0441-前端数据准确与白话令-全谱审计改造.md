# T-0441 前端数据准确与白话令——全谱审计改造

- 状态：待验（施工收口 2026-11-08——全谱审计+整改落账见末节；原批：业主令 2026-11-07 原话：「1、前端所有数据必须是准确的，不得使用含糊/过时。2、表达尽量准确无黑话」）
- 归口：外派外审径（工程面——前端文案/数源标注/口径显示，非钱径）
- 领取：外派
- 依据：业主令两条 = 全前端普适质量标准，非单点修——按「全谱审计→逐条整改→回归断言」形制立票

## 病根（已实证三例，非穷举）

1. **态标错**：`fin_armed`（武装待扳机候选，持仓=0）前端标「执行中」——
   33 个候选被读成 33 单在跑，语义级误导（业主亲验 2026-11-07）。
2. **币种混淆**：账实差告警/前端把 CORE 币量 3813.34 贴 `$` 标显示成
   「$3813.34」——币量与 USD 等价两个口径混一列（实证：告警体原文）。
3. **黑话裸出**：`fin_armed`/`谱域缺行`/`fin_retired` 等机内枚举值
   直接当用户可见文案——业主令「无黑话」。

## 钦定整改（三轴）

- **①数准轴**：前端每格数据须可溯源到后端真源字段+鲜度——凡渲染口径
  与源字段语义不符者（armed→执行中 类）全部改对；陈数据按 T-0434
  既有硬闸形制置灰/红标，禁以旧数冒充新数。
- **②白话轴**：机内枚举/字段名禁裸出——建「机读态→人读词」映射层
  （armed→「候选就绪/待触发」、proposed→「评估中」、adopted→「已开仓」等，
  词表以票面词为准），告警体币种与 USD 等价分两列标注（`3813.34 CORE
  ≈$48.9` 非 `$3813.34`）。
- **③全谱轴**：审计范围=React 前端全部页面+告警/通知文案模板，
  逐格对源字段语义与币种单位，产出违例清单逐条整改——禁只修三例
  已知项交差。

## 禁线

- 不改后端口径/账本语义——本票只管「显示层忠实翻译」；
- 词表映射进代码常量或配置面（禁散在各组件硬编码——同 0440 通用性律）；
- 不借本票重构 UI 框架/换库——改动面限文案映射+口径分列+鲜度标注。

## 范围（DM 钦定回填 2026-11-08——机派裁定行3881：外派径断链回收内环）

1. 文件路径钦定：`web/src/react/**`（React 前端全部页面/组件/样式——审计+整改主面；
   词表映射层/口径分列/鲜度标注落点由施工在本面内定）；
   `internal/platform/notify/**`（告警/通知文案模板——文本翻译面，禁动逻辑口径）；
   `web/scripts/flowpulse-domtest.mjs`（domtest 期望词同步跟随件——票面文案整改
   的必然跟随、验收①绿对口必需；CTO 裁域追认 2026-11-08，详裁决行）；
   `docs/tasks/T-0441-前端数据准确与白话令-全谱审计改造.md`（票回填+违例清单落账）。
2. 整改产物=违例清单逐条对账（审计产出落票面，零遗漏）；
