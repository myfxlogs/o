# T-0504 研究员触发侧断线根修——新品/达阈事件落账无消费拉起径

- 状态：已批（CTO 自立——T-0502 施工范围外呈裁观察坐实）
- 级别：P2 进水口接线面——与 T-0502 同型断线的上游半段：送径已
  接（T-0502），触发源本身无人消费=研究员永远不会被拉起

## 病灶（2026-11-09 CTO 复核实证）

D-0043/研究员 SKILL 钦定两触发：T-0300 venue 达阈事件／venue 新品事件
（seat=venue哨兵 ops_event '新品' 行，venue_watch.sh 落账在案）。实测：

1. `venue_watch.sh` 落 `seat=venue哨兵,event=新品` 行——全仓 grep
   `新品` 消费面零命中（scripts//internal//cmd/ 无读取者）；
2. 研究员无守护/拉起件——无 systemd unit/timer 消费 ops_event
   拉起研究员会话（对照施工席 dispatch_worker.sh/CEO ceo_tick.sh
   全缺）；事件落账即成死信；
3. T-0300 达阈事件同型——无写者亦无读者，第二触发从未接线。

即：研究员生命周期两端皆断——T-0502 修了「产出→CEO」下行段，
本票修「事件→拉起」上行段；不修则 T-0502 所接送径永远无货可送。

## 范围（候选方案择一钦定后回填）

1. 消费径设计：照 `dispatch_worker.sh`/`ceo_tick.sh` 同构——
   `scripts/meta/researcher_tick.sh`（PG advisory 单例+滤队 SQL
   `seat=venue哨兵,event=新品` 未终态行→拉起研究员瞬态 run）
   或并入既有 tick 壳轨——施工先出设计段呈 CTO 钦定再动工；
2. `scripts/meta/venue_watch.sh` 头注「→研究员触发信号」补落
   实际消费径名（文档与码面一致）；
3. T-0300 达阈事件：补写者（venue 评估面达阈落同型触发行）或
   票面显式退役该触发（二选一，涉 D-0043 钦定闭集——退役=升件
   呈业主不擅动）；
4. 桩测：合成新品事件行→tick 滤队命中；消费落终态行后不再命中。

## 判据

1. 新品事件有真实消费拉起径（桩测合成事件→拉起调用实证）；
2. venue_watch.sh 头注消费径名与实际一致；
3. T-0300 达阈触发：接线落地或升件退役有明文去向（不留悬空）；
4. 全谱零新增 FAIL/SKIP；先红桩——消费缺席断言修前红（合成事件
   落账→滤队空/拉起零调用），同断言修后绿。
