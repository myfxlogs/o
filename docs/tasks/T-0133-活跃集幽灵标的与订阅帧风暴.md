# T-0133 活跃集幽灵标的与订阅帧风暴（急件·T-0132 漏面）

## 实证（SG 2026-10-25 18:05 部署后）

T-0132 上线即现两类服务端 error 帧（生产日志实证）：

1. **60018 幽灵标的**：`tickers,instId:ETH-USDT-261029-2590-C doesn't exist`——DCD 产品名（`-\d{6}-\d+-[CP]$` 期权形）非行情标的，OKX 期权为币本位 `ETH-USD-*`，USDT 期权 instId 不存在。规模：`fin_proposal` armed 967 行含 748 期权形 + proposed 244 全期权形（activeSet 全集 1008 标的，~992 幽灵）。每帧独立 WriteJSON 且 `subTick[inst]=true` 记在写成功后——server 拒收不清标记，但**每次重连 subTick 重置全量重发**，错误随重连周期复炸（实测 268 帧/2min）。
2. **60014 限频**：boot/重连时活跃集 1008 标的逐帧连发无分批无节流——合法 tickers 订阅被限频帧随机吞掉且不重试（`subTick` 已标记），活跃标的漏订至下次重连才有机会补上。

数据面未死（md_ticks 1s 鲜、md_mark_index 41s 鲜）——定性=噪声+限频风险面，非断流。

## 修法

1. **活跃集过滤**：`syncActive` 只对「在订阅宇宙 syms 内」的 inst_id 发 tickers——dialLoop 建 `valid := set(syms)`，幽灵 inst_id（DCD 产品名及一切非真实标的）天然被滤，不修 DB 提案数据（提案本身是假想链产物，执行面另议）。
2. **加订分帧节流**：初始 syncActive 加订复用 subscribeAll 式 ≤100 args/帧+帧间节流；30s diff 增量小可留单帧，但同函数统一走分帧件更稳。
3. **（可选）60018 黑名单**：error 帧带 instId 时记拒收集，本连接内不再重发——防线②的兜底。

## 验收锚

- 部署后 10min 日志：`Subscribe failed`/`60014` 帧=0；重连（若发生）后同=0
- `md_ticks` 活跃集 inst_id ts<10s；`md_mark_index` 宇宙行 ts<5min
- 单测：activeSet 含幽灵 inst_id 时 syncActive 不发其 tickers 帧；>100 标的活跃集初始加订分帧
- 棘轮/机检全绿

## 结果回填

- ①活跃集∩宇宙滤除：dialLoop 建 `valid=set(syms)`——activeSet inst_id
  不在订阅宇宙内不发 tickers 帧（DCD 产品名/假想链产物天然滤除，
  DB 提案数据零动）。
- ②加订分帧节流：syncActive 加订复用 subscribeAll ≤100 args/帧+50ms
  节流（60014 限频实证）；退订单帧面不动。
- ③60018 拒收集：error 帧带 instId→refuseSub 记本连接内不重发。
- 桩测：ghost_test.go 三锚（分帧 150=2 帧/幽灵滤除/拒收集不重发）绿。
