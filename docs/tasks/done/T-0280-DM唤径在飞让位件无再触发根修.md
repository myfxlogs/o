## 背景（根因已定位，勿重复诊断）

directive 落 DM 箱时席在飞 → `mbus-dispatch.sh spawn_dm` flock 预检失败走
`{ log "DM 在飞——件留箱自收"; return; }`（`:243`）——件留箱等「自收」；
但在飞 DM 会话（`dm-spawn.sh`）善终兜底段**只 ack 任务书关联件**（grep
prompt 内 msg id 逐件 ack），余箱不扫不收；锁释后**无任何事件/补扫再
触发**——dispatcher 的 DM 箱 directive 补扫只在 `boot_sweep`（`:881` 起
RTRFIX 段，仅 daemon restart 执行一次）。结果：件滞留至 EDR deadline
起 L1→L2→L3 升级链。

实证链（本票触发案）：探针 `20261031-212343-DM-3290` 21:23:43 落箱时 DM
在飞让位，在飞席 21:37 收盘未代收 → 21:53:48 L1（3331）→ 22:23:48 L2
（3374）→ 管理席 MANAGE-3378 人工收链。

同日第一次实证：MANAGE-3334 核结「唤径在飞期让位正常、无再触发径
（已知 3106 同型）」——MANAGE-3106/3251 案修的是「办结不回 ack」wrapper
兜底，本案是「在飞期落件无重唤」缺口，**同族不同病灶**，勿并案。

## 钦定界（根修方向，施工裁具体式）

- [ ] **在飞让位件有重唤径**——三选一或组合（施工裁）：
  a. dispatcher 增「DM 会话终/DM_LOCK 释锁」侦测点 → 走既有门2-DM 补扫
     段重唤；
  b. `dm-spawn.sh` 收盘段加余箱扫——兜底 ack 后查 DM 箱残余未 ack
     directive，有则自举下一次唤（链式唤）或回投 dispatcher 事件；
  c. 让位时落「待唤」标（如 `.pending-dm`），任一既有周期扫点
     （extaudit/rework 同节流径）命中即重唤。
- [ ] 幂等锚沿用现成三段（spawn_dm 锁预检 + dm-spawn.sh 内锁 + `.spawned`
  claim）——同件不叠唤、不并发唤。
- [ ] 桩测+实证：「DM 在飞 + directive 落箱 → 在飞收盘 → 自动重唤消费」
  全链跑通；3290 型自举探针（DM→DM directive）落箱在飞场景收盘后无人
  介入自动消费，不产生 EDR 升级件。
