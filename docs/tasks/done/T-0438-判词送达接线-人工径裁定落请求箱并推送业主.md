## 病灶

需业主动作的判词（人工径执行/凭据缺口/授权项）落
ops_event 即止——无 condition_gap 请求行、无 feishu
推送；业主侧无「要我动手」视图，件卡死静默。
既有件可复用：fin_condition_gap 请求箱（kind=holding/
executor/credential）+feishu-notify 推送径在产——缺的是
判词→两径的接线。

## 面（钦定）

① **判词分类识别**：ops_event 裁决/通过/驳回行 note 含
   「人工径/业主在场/需业主/凭据缺口」类词→判业主
   动作件（词表钉票面不猜——首版列钉死可后扩）；
② **condition_gap 转写**：命中→INSERT fin_condition_gap
   （kind=holding 或 executor，ref=ops_event 行 id+ticket
   +判词摘要+需动作明细）——请求箱是业主唯一动作视图；
③ **推送径**：同拍 feishu-notify 推送行「⚠ 需业主：
   T-NNNN <判词一行>」——复用现有推送载（cmd/feishu-
   notify 或 notify 包在产径，先查现成不新造）；
④ **幂等防刷**：同 ops_event 行只转一次（ref 行幂等键——
   event id 唯一索引/dedupe 表，连鸣件不连推）；
⑤ **载位**：挂既有周期件（o-gauges-tick/eventbus 消费面
   ——查现成载，新造进程=新死亡面，宁搭车不新造）。

### 设计裁定（审裁请对锚）

- **词表钉死**（票①）：`人工径|业主在场|需业主|凭据缺口` 子串字面
  （O_VERDICT_KEYWORDS 覆写=桩测面）；词→kind 映射：凭据缺口→credential，
  余→executor（箱 kind 闭集语义；票②「holding 或 executor」之 holding
  首版无词映射留箱不用——审裁可裁）。
- **venue/surface 语义**：venue=<票号> surface=verdict——箱 pending 唯一
  键 (venue,surface,kind) 由此 per-票 per-kind 一行：同票连裁刷同行不刷屏，
  异票异行不互撞（箱惯例 venue=平台名，此处动作视图行以票号定位=语义
  扩展声明，审裁可裁）。
- **对行防连推**：决策席同判词「裁决+通过/驳回」成对双行（同票同 note
  实证 90/101）——(ticket,note) 首现行（rn=1）唯一转写。
- **幂等键**（票④）：ops_event 送达标记行（event=`送达`，seat=META-DM，
  **ticket=''零票态污染**——dm_queue/工作台按 ticket 取 latest，带票号
  标记行会藏收口行；票号在 note），note 前缀 `ref=<event_id>|` 即键；
  箱成→推送成双成才落标记；推送败=零标记下拍重试（箱 upsert 刷新无害）；
  **箱写败=零推送零标记**（箱=业主唯一动作视图，只推不落箱=半途断链
  违票②义——宁滞留重试显形于 rc≠0→dm_tick 升件 24h 去重）。
- **箱写径单源**：BOX_DSN=FIN_DSN（roster_rw）——SG 正本箱写主机面唯
  柱级授权径。实勘：roster_rw 对箱零授权→**迁移 fin_0139**（fin_0113
  research_rw 同形：INSERT 全表+SELECT 限列+UPDATE(requested_at,payload)
