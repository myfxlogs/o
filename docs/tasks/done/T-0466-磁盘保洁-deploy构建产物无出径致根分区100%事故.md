# T-0466 磁盘保洁——deploy 构建产物无出径致根分区 100% 事故

立项：2026-11-08 业主「96G 这么大？再好的服务器也会被拉跨」+ 异常行实证（check_all go build link 撞根分区 100% 被打断，T-0460 外派途中的连带事故）。

## 病灶（实测量）

| 肥源 | 峰值占用 | 出径 |
|---|---|---|
| docker build cache | 141.5G（857 条记录，全 reclaimable） | **无**——deploy_image 每次构建只进不出 |
| go build cache | 69G（已 go clean →524M） | 无界，check_all/deploy 复跑即长 |
| docker 镜像堆 | 66 个 o-core:<sha> tag（每个 ~70M≈5G）+ golang/node/timescaledb 基底 | **无保留窗**——一 commit 一 tag 永不删 |

check_all 的 go build link 只是压死骆驼的最后一根稻草（link 需数 G 临时位撞上 100%）。

## 事故链

deploy 无 prune → build cache/镜像堆单向增长 → 根分区 100% → check_all 被打断 → 部署链停。不清源，数月后必再犯。

## 裁域（CTO 填）

1. **build cache 定期清**：o-wt-gc 同款 systemd timer 跑 `docker builder prune -f`（如周清或超阈清）——纯缓存删了只让下次 build 慢，零损。
2. **镜像保留窗**：deploy_image.sh 尾部加「保留近 N 个 sha tag + latest」（N 待裁，建议 ≥5 保回滚径）——删 tag 不动在用镜像。
3. **go cache 界**：`GOCACHE` 上限 env 或 cron `go clean -cache`（go 本体无内建上限，须外面卡）。
4. **告警面**：根分区 >85% 走 gauges/经营事件——今天 100% 是靠 check_all 撞死才发现的。
5. **等锁盲区消**（业主令 11-08 追裁）：check_all 进等锁段即落 ops_event 行——当前等锁只写进该 run 自己的 log，外人不可见；无头席撞锁只见「败了重试→再撞」，傻等不可见即不可治。
6. **孤儿锁清扫**：持锁 fd 进程 ppid=1（父死）=孤儿→杀+报——实证：kill 掉 check_all wrapper 其孵化的 `go test ./...` 树成孤儿持 fd9 锁 15min+，新跑傻等。周期扫挂 o-wt-gc 同款 timer。
7. **GOCACHE 分家**：按 worktree 分目录（`GOCACHE=/tmp/gocache-<topkey>`）——实证并发跑互逐致「非码面红」（T-0458 外审裁记栽过）；wt-gc 顺手清目录，盘代价换假红绝种。
8. **advisory herd**（T-0460 工人 11-08 异常行实证）：并发跑共享测试资源时 cmd/core 30min 超时一次——与 ⑤⑥⑦ 同域并发病灶，裁是否要运行级互斥/错峰或仅监控。

## 已先做（本票外的机械救急，COS 域）

- `docker builder prune -af`：141.5G 清毕，根分区 359G→229G（可用 199G，85%→54%）
- go cache：前手 `go clean -cache` 已释 69G

- 磁盘高水位有告警源，不靠撞死发现

## CTO 裁定回填（2026-11-08 班裁——裁域八件定案翻已批）

1. **build cache 定期清**：o-wt-gc 同款 systemd timer 双触发——周清（周拍）+高水位清（根分区 >80% 即 prune），`docker builder prune -f`（纯缓存零损，下次 build 仅慢）。
2. **镜像保留窗**：deploy_image.sh 尾段保近 N=5 个 o-core:<sha> tag+latest——N=5 覆盖近窗部署史保回滚径，删 tag 不动在用镜像。
3. **go cache 界**：同一保洁 timer 周跑 `go clean -cache`；⑦分家落地后按 wt 目录清量（分家先落，cache 界与⑦联动——清孤儿 wt 目录即清量）。
4. **告警面**：gauges.tsv 新行 `rootfs_highwater`（kind=淤积——根分区利用率>85% 阈=1 连鸣），不靠撞死发现。
5. **等锁盲区消**：check_all 入等锁段即落 ops_event `等锁` 行（seat=跑席，note=锁 key+holder pid+锁龄），拿锁/超时各补一行——等锁面外人可观测。
6. **孤儿锁清扫**：o-wt-gc 同款 timer 30min 扫——锁 fd 持有者 ppid=1（父死）=孤儿→杀持 fd 进程树+ops_event 报行。
7. **GOCACHE 分家**：check_all.sh 头设 `GOCACHE=${GOCACHE:-/tmp/gocache-<topkey>}`（topkey=checkout 路径 hash 同锁键）——并发跑互逐绝种（T-0458 假红实证）；wt-gc 顺手清对应目录。
8. **advisory herd**：首版监控不互斥——gauges 行报并发 check_all 跑数+go test 超时率（testdb lease 族池已分 DB 资源；运行级互斥=吞吐死，错峰证据不足不先造）；连续超时超标再裁运行级错峰（拿数据再裁）。

## 结果回填（施工 2026-11-08）

### 实现摘要（裁域八件+范围七件全落）

- **件①builder prune 双触发**：`wt_gc.sh` 保洁面 `disk_hygiene()`——
  周拍（`/var/tmp/o-wt-gc.last_prune` mark>7d）→`docker builder
  prune -f`；根分区>80% 高水位→`docker builder prune -af`
  （裁填：高水位档用 -af——141.5G 实证 -f 只收 dangling 不够，
  周拍常规档守 -f 钦定原文）。mark 节流内建=「周拍」语义。
- **件②镜像保留窗**：新 `scripts/meta/image_tag_gc.sh`——
  CreatedAt 降序留近 N=5 sha tag+latest（O_IMAGE_KEEP 覆写），
  `docker rmi` 只摘 tag（在用镜像/容器零触）+dangling prune -f
  收口；`deploy_image.sh` 尾段调用（保洁尽力——败不翻部署结果，
  tolerate 锚在案）。docker 桩测实证剪最旧三/留最新+latest。
- **件③go cache 界**：周拍 `go clean -cache`（GCLEAN_MARK>7d
  节流）+`/tmp/gocache-<topkey>` 分家目录三闸清（活 wt 键集外
  ∧对应锁未持∧龄>24h——锁文件绝不删，删了双 inode 锁互斥破）。
- **件④告警面**：`gauges.tsv` 新行 `rootfs_highwater`（淤积/
  cmd/df / Use%/阈86= >85%/mode=连鸣——冻结类阈上持续发声）；
  另两观测行 `checkall_inflight`（竞态/在持锁跑数/阈4）+
  `checkall_envcontention_24h`（竞态/24h 内 .mode 含
  env-contention 戳数/阈2）——裁定⑧「首版监控不互斥拿数据
  再裁」落地。
- **件⑤等锁盲区消**：`check_all.sh` 锁段 `oe_lock()`——入等锁/
  等锁超时/锁到手三落点各落 ops_event（seat=跑席 ticket=T-0466，
  note=key+holder pid+holder etimes 锁龄；DSN 缺席/写败静默退
  审计件非硬闸）。holder 龄改取 `ps etimes`（锁文件 mtime 恒新
  无信息量——自审修正）。
- **件⑥孤儿锁清扫**：`disk_hygiene()` ⑤段——GC_LOCK_GLOB 内
  锁逐把 fuser 持fd集，`orph_ppid()` 判父死（ppid=1 ∨ 父comm=
  systemd——subreaper 两形，见上方修裁附录）→杀子孙树+本体+
  ops_event 报行；父活跑者不碰；--dry-run 只检不杀（干跑零动律）。
- **件⑦GOCACHE 分家**：`check_all.sh` 头 `export
  GOCACHE=${GOCACHE:-/tmp/gocache-${TOPKEY}}`（TOPKEY=同锁键
  pwd -P|sha256sum|cut -c1-16——用户预设 GOCACHE 尊重不覆写）；
  并发跑互逐「非码面红」绝种，代价=目录随 wt 生——wt_gc 三闸清。
- **件⑧advisory herd**：按裁定=监控不互斥——gauges 两观测行
