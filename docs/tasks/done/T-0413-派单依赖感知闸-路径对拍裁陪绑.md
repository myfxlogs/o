- 收口移交归：决策席

## 背景（实锤病灶）

DM 班次=单席串行全轨（审计/派单/merge 同桌面）。实证 11-06：
T-0412 已批→派单间隔 11min——只因 DM 在裁 0414/0409（in-flight
班次内 rescan 吸收），而 0412 施工面（quotes_face/提醒径）与在审
分支（scripts/check_all）**路径零交集**——下游件等得有理，
平行件等是纯浪费。业主裁词：「审计返修=基础不牢，新票建在错基
上不行；若不依赖就不该陪绑」。

## 钦定语义

```
派单道前置闸:  kick到(或班内rescan扫到已批件)→先算
             候选票施工范围 ∩ 在审分支diff路径集
  空交集   → 即派——不等班序,事件直驱(systemd-run拉起)
  有交集   → 进班排队等裁决——依赖件不许先跑(防建错基)
  不可判   → 排队(保守缺省——范围写不清的票不配加速)
范围来源: 票面「范围」节文件清单(现有约定)+分支merge-base diff
         ——两源并集,判的是路径集不是语义
```

## 范围

1. 对拍件：新票范围路径集提取（票面解析）×在审分支
   `git diff --name-only merge-base...HEAD`→交集判定
   （shell 或 go，择最小改面——dm_queue.sh/dispatch_worker.sh
   现径挂点）；
2. 即派径：空交集票绕班序直拉 o-worker（写 ops_event 派单同拍，
   账径不变）；
3. 排队径：交集/不可判照现规入班（行为不变）；
4. 票面「范围」节清单规范补强：缺清单=不可判排队（自然激励
   票面写准）；
5. 探针：对拍败/范围空读的票落升件而非静默排队。

## 验收

- 红桩①：在审分支 diff=A 路径集，候选票范围=B 零交集→即派
  （ops_event 派单行时戳<班内下一 rescan 证明没等）；
- 红桩②：范围∩diff 非空→排队至裁决后（依赖串行保住）；
- 红桩③：票面无范围清单→排队（缺省保守）；
- 实证：今晚 0412-型场景回放（票面范围 vs 0409 diff=空→即派）；
- 绿戳对口+全链。
