## 病灶链（生产实证全链）

1. **LISTEN 连接池污染**：`platform/events.listenOnce` 用 pgxpool
   借连接，`LISTEN` 是会话级常驻——连接还池时未 `UNLISTEN *`，
   下任借用者继承全部频道残留。
2. **T-0126 把 ev_eval 扩成高频频道**（INSERT OR UPDATE 每拍必发）：
   被污染的连接让 funding 扫描环被 ev_eval 持续唤醒。
3. **自激闭环**：扫拍→eval upsert→ev_eval 发→唤醒扫拍→……
   每轮 513 标的，~83 INSERT/s。
4. **提案去重洞**：`funding/run.go:174` 只查 `state='fin_proposed'`——
   lifecycle 消费成 armed/retired 后下拍重插，`fin_proposal` 10 分钟
   +39,739 行。

## 临时止血（决策席已在产，迁移固化属本票）

- `fin_proposal` BEFORE INSERT 去重触发器（同 inst_id+direction 存在
  proposed/armed 即跳过）——**洪泛 5k→0 行/分实证**。
- 此触发器须在迁移序列正式落册（幂等版），否则新部署不带闸。

## 修法方向（施工裁）

- **A. listenOnce 归还前 `UNLISTEN *`**（defer）——断频道污染根；
- **B. persist 去重升级为「同键 live 提案或 active 策略」**——
  armed/live 策略在册即不再提案；
- **C. 提案表去重触发器入迁移**（含幂等 IF NOT EXISTS 形）；
- **D. 清污**：fin_proposal 洪泛期 fin_retired 死行 ~24 万清史+
  VACUUM（保留真审计链——清洪泛窗段的机械判定：洪泛窗内
  created_at×state=fin_retired 且同键超过 N 次的行）。

## 验收锚

- 拔掉临时触发器后提案增速=机会真速率（分钟级个位数）
- 长跑 1h：fin_proposal/fin_opp_eval 行数封顶；ev_* 唤醒与写面一一对应
- 桩测：同键 active 策略在册→persist 不再插提案行
