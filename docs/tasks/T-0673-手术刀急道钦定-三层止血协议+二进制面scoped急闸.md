# T-0673 手术刀急道钦定——三层止血协议+二进制面 scoped 急闸

- 状态：候选（业主令「手术刀就应该抢在问题前面，止血」——待 DM/COS 裁）
- 领取：常径待派
- 优先级：P1（下次 P1 出血时救命用——本身是协议件可等批）
- 收口移交归：决策席
- 立项：业主令两连 2026-11-09——「如果手术刀也要等拍片时间，那就
  起不到止血的作用」+「这个协议是 COS 外部的特权，也是督察/监管/
  止血的1个通道」
- **协议定性：COS 外部特权通道**——非内联快道。督察/监管/止血三
  合一，监管对象含机器自循环本身（其失灵或过载时本通道是旁路）。
  不取代 DM/COS 常径——是常径失效/过慢时的平行处置径。

## 病灶

止血动作被绑在落账动作后面——master 推闸绑绿戳（fail-closed
钉死），急诊修复被迫排队等全谱 check_all（15-20min）+merge+部署
链。T-0517 实证：让号+rebase 撞两次重戳。但「止血=让产线停血」
与「落账=fix 进 master」是两层——多数出血层根本不经 master 闸。
且通道须独立于被监管对象：机器自循环病时（如起草拍烧号），内联
径本身即是病灶一部分，特权通道须在其外。

## 断言（验收判据）

1. **三层止血协议落 AGENTS/职卡**（文字钦定即可）：
   - 数据面（队列行/僵尸行/批销）：直改产库+ops_event 落账行——
     不动码零戳（本径 2026-11-09 实证：482 笔草案批销秒级止血）。
   - 脚本面（gateway/meta/timer 等活读 .sh）：补 /opt/o 活文件
     →下一拍生效；同 diff commit 走戳殿后；殿后戳败=prod 文件
     回滚+升件（prod 文件与 commit 必须逐字节同——可验证）。
   - 二进制面（o-core/SG 镜像）：scoped 急闸——语法+受影响包测
     （秒-分钟）→merge→部署→全谱 check_all 殿后验，败=自动
     回滚告警升件（check_all 现 scoped 模式即此形态，钦定为急诊
     合法门槛）。
2. **持通道人**：业主令授权的外席（O-Dev 手术刀径实证）+CEO 急诊
   权（AGENTS 既有「急诊 P1 立票 CTO 事后会签」）；非授权席自称
   手术刀无效——督察面含对通道自身的审计（每刀落账可回放）。
3. **记账纪律**：手术刀动作一律 ops_event 落行（seat/对象/判据），
   票面尾随根修票——止血不等票，但账不能少；监管职能依赖账面
   可回放，无账之刀=违例。
4. **界定**：不碰钱径语义/风险闸/方向锚（业主红线三件不动）；
   通道监内不监上——对业主只报事实与所需动作。
