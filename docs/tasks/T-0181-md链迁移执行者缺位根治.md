## 病灶（验收实证）

md_1071（T-0171 落）从未在 PG-md 应用——库卡 1070 直到 T-0178 验收手补。
根因**不对称**：fin 链有天然执行者（SG o-core boot 必 `Migrate(fin)`，
每次镜像轮换=schema 自追）；md 链的迁移者是 projector/sweeper——boot 迁
没错，但**部署序里没有「md 迁移落地」这一拍**，它们的重启不在 dev 部署径
上。结果：md_* 迁移合入即「已合并≠已执行」灰色态，谁都没发现（直到
updated_by 缺列暴露）。

同类残留：`fin_proposal_id_seq` 键空间撞 SG（projector boot 守卫拦住，
已 setval 300000 救急——守卫本身是功德，证明「md 侧无自动执行者」期
间键空间漂移无人管）。

## 施工面（两件，对称根治）

1. **o-research boot 背 md 迁移闸**：`cmd/research` 主流程在 pool 建后
   `pgstore.Migrate(ctx, mdPool, "md")`——与 SG o-core `Migrate(fin)`
   完全对称。dev 部署必重启 research=md schema 自此随每次换件自追，
   灰色态物理消失。
   （projector/sweeper 的既有 boot 迁移保留——幂等无害，多执行者=
   迁移锁自有串行化在 Migrate 内。）

2. **漂移哨兵入验收序**：scripts/ 加 `check_schema_live.sh`——对 SG fin
   与 dev md 各查 `max(schema_migrations.version)` 对照登记表最大号，
   落后即红。挂进 deploy_sync.sh 尾部（或验收 checklist 机械步）——
   「合并≠执行」今后由机器报，不靠下次撞出来。

## 禁线

- 不改 Migrate 幂等/锁语义；不引入第三执行者框架。
- 哨兵只读对照，不自动补迁（补迁权=人/服务显式动作）。

## 验收锚

1. 任一 md_* 迁移合入→research 重启→PG-md max(version) 自追，零手跑。
2. check_schema_live 对人工制造的落后面报红（桩验）。
3. T-0171 型漏迁事故复现路径被哨兵截获（回归锚）。

## 决策席返修（验收实拍返工——哨兵探针打错库）

桩验实拍：`check_schema_live.sh` 在 dev 跑报
`FAIL fin live=53<73`——**打的是 dev 本地 o-postgres 残骸容器**
（分域切割前的旧 fin 库，schema 冻 53），不是 SG 真库（真库=73 已在册）。
`docker port o-postgres` 在 dev 上捡到的是死尸——按此逻辑哨兵将
**每次部署永红（狼来了失效）**，且真落后反而淹没。

**修法钦定**（二选一，倾向①——与 deploy_sync 同拓扑、零新凭据）：
1. SG 侧探针改走部署同款 SSH 径：`ssh $O_SG_HOST docker exec o-postgres
   psql ...`（deploy_sync.sh 里 `SG="${O_SG_HOST:-root@192.229.85.35}"`
   变量现成）——真库权威性 SG 本机口径。
2. 或 dev 侧读隧道 DSN（FIN_PG_DSN/5544）——但那是 research 专用隧道，
   哨兵不该绑某个服务的 env 文件。

md 探针（本地 o-postgres-md 探测）正确，保留。fin 探针只有 SSH 径
或显式传参两种合法源——禁 docker port 自动探测（正是本次踩坑面）。

另：dev `o-postgres` 残骸容器已 stop（切割遗留死件，卷暂留可逆——
卷删不删=另案数据账裁定）。
