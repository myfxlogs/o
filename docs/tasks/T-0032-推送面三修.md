## 背景（三病灶实证）

1. **报表刷屏**：`pushIfDue` 以 `generated_at<30s` 判新行——但 `Gen` 每拍 UPSERT 刷 `generated_at=now()`，「新行」恒真 → **每 30s 推 3 条 ≈8640/日**。根因：用错判据（应判 `period_start` 滚动而非 generated_at 新鲜度）。
2. **typed-nil 崩环**：`NewAlerter` 入参 `Sender` 接口装 `(*FeishuClient)(nil)` 时 `a.cli==nil` 不成立→`SendText` 调 nil receiver 方法→panic（SG creds 缺席实测崩环 Restarting(2)）。根因：接口装类型化 nil 非 nil；装配处凭据缺席应传 nil 接口或 Alerter 内判。
3. **持续告警=变相刷屏**：同指纹去抖仅 5min——长期态告警（如对账差未平）每 5min 一条≈288/日。根因：持续性事件只退抖不退避。

## 交付物

1. **报表推送按期界语义**：推且仅推「period_start 新滚」——追踪 last-pushed（period,period_start)（库表或进程内记录均可，重启不重复推当期行）；期界滚动→该行首生成拍推一次；同 period_start 的 UPSERT 重跑不再推。
2. **Alerter typed-nil 根修**：装配点凭据缺席传 nil `Sender`（非 `(*FeishuClient)(nil)`）或 Alerter.Alert 增 typed-nil 判（反射/可空接口二选一，注释钉因）；补测试锚：typed-nil 注入不炸。
3. **持续告警退避**：同指纹推送间隔 5min→指数退避上限 1h（5→10→20→40→60 顶），指纹变=重置；`kill_switch`/dd 触线等瞬时事件不受退避影响（首报即时）。
4. `notify.feishu.enabled` 恢复 true（修后重推 SG+dev——现停用止血中）。
